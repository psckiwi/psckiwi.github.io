시작 전 준비 — 설치·가입·브라우저 데이터·비밀번호 가져오기

Aside 는 웹사이트·계정·방문 기록을 써서 복잡한 일을 해내는 AI 브라우저입니다. 실습을 하려면 먼저 Aside 를 설치하고, 계정으로 로그인하고, 지금 쓰는 브라우저의 자료와 비밀번호를 옮겨 옵니다. 이 장은 그 준비를 처음부터 끝까지 한 단계씩 따라 합니다.

이 준비를 마치면 할 수 있게 되는 것
  • 내 컴퓨터(macOS 또는 Windows)에 Aside 를 설치하고 엽니다.
  • 계정을 만들거나 로그인하고, 쓰던 브라우저의 방문 기록·쿠키·북마크를 가져옵니다.
  • 다른 비밀번호 관리자에 있던 비밀번호를 Aside 로 옮깁니다.
  • 에이전트(사람 대신 브라우저를 조작해 일하는 AI)에게 첫 작업(에이전트에게 맡기는 일 하나)을 보낼 준비가 끝납니다.
처음이라면 이 순서로

준비물을 확인하고 → 따라 하기 네 단계를 차례로 진행한 뒤 → 잘 됐는지 확인합니다. 중간에 멈추면 막히면에서 같은 증상을 찾으세요. 준비가 끝나면 실습 1로 넘어갑니다.

SCENARIO 1

새 탭에서 Ask AI 로 첫 작업 보내기 — 영수증 PDF 를 경비 보고서 표로

Aside 에 처음으로 일을 맡겨 봅니다. 새 탭 입력창을 Ask AI(AI 에게 맡기기 — 검색 대신 에이전트에게 일을 보내는 모드)로 바꾸고, "Downloads 폴더의 영수증 PDF 들을 경비 보고서 표로 만들어 달라"는 요청문 한 줄을 보냅니다. 원문이 Ask AI 예시로 드는 바로 그 일입니다.

이 실습으로 할 수 있게 되는 것
  • 새 탭 입력창에서 Search(검색)와 Ask AI 를 구분하고, Ask AI 로 작업(에이전트에게 맡기는 일 하나)을 시작합니다.
  • "어떤 자료로 · 무엇을 만들지 · 무엇을 넣을지"가 담긴 요청문(prompt — 에이전트에게 써 보내는 글)을 씁니다.
  • 파일을 다루는 작업에서 권한 모드와 작업 폴더를 고릅니다.
  • 작업이 만든 파일을 작업 상세 페이지에서 확인합니다.
처음이라면 이 순서로

준비물을 갖춘 뒤 → 따라 하기 다섯 단계를 진행하고 → 잘 됐는지 확인합니다. 작업이 멈추거나 결과가 엉뚱하면 막히면을 봅니다.

준비물

  • 시작 전 준비를 마쳐, Aside 가 열리고 내 계정으로 로그인되어 있습니다.
  • Downloads(다운로드) 폴더에 영수증 PDF 파일이 몇 개 들어 있습니다. 연습이니 두세 장이면 충분하고, 남에게 보여도 괜찮은 영수증으로 고릅니다.
  • 영수증에서 뽑고 싶은 항목을 정합니다. 이 실습은 원문 예시대로 날짜 · 가맹점 · 합계 · 결제 수단 네 가지입니다.
Ask AI 는 무엇이 다른가요?검색창에 낱말을 넣으면 "관련 페이지 목록"이 돌아옵니다. Ask AI 에 일을 적어 보내면 에이전트(사람 대신 브라우저를 조작해 일하는 AI)가 그 일을 직접 해서 "결과물"을 돌려줍니다. 길을 묻는 것과, 심부름을 보내는 것의 차이입니다.

따라 하기

1단계 · 새 탭을 열고 입력창을 Ask AI 로 바꾸기

  1. 새 탭 열기새 탭의 입력창(omnibox — 주소나 검색어를 넣는 긴 칸)이 보입니다. 이 입력창에는 Search(검색)와 Ask AI 두 가지 모드가 있습니다.
  2. Ask AI 고르기모드를 Ask AI 로 바꿉니다. 모드를 바꾸는 곳의 정확한 위치는 원문에 적혀 있지 않으니 화면에서 두 이름을 찾아 고릅니다.
  3. 또는 단축키 쓰기Cmd/Ctrl+E 를 누르면 Ask Aside(Aside 에게 묻기)가 시작됩니다. macOS 는 Cmd, Windows 는 Ctrl 키입니다.

확인: 입력창이 Ask AI 모드로 바뀌었습니다. 원문에 따르면 작업 입력창(composer)에는 Ask AI a task, @ for context(AI 에게 작업을 맡기세요, @ 로 맥락 추가)라는 안내 글자가 쓰여 있습니다.

2단계 · 요청문 쓰기

아래는 원문의 「Receipt expense report」(영수증 경비 보고서) 예시를 한국어로 옮긴 문장입니다. 원문 예시는 영어이므로 영어 문장도 함께 싣습니다. 복사해서 입력창에 붙여 넣습니다.

보낼 요청문 
Downloads 폴더에 있는 영수증 PDF 들을 경비 보고서 스프레드시트로 정리해 줘. 열은 날짜, 가맹점, 합계, 결제 수단으로 해 줘.

원문(영어)

Turn the receipt PDFs in Downloads into an expense report spreadsheet with date, merchant, total, and payment method.

스프레드시트(spreadsheet — 엑셀처럼 칸과 줄로 된 표 파일)를 만들어 달라는 한 문장이지만, 에이전트가 헤매지 않게 하는 세 가지가 다 들어 있습니다.

막연한 요청은 피합니다원문은 Handle my billing.(내 결제 좀 처리해 줘) 같은 요청을 "너무 막연하다"고 짚습니다. 어느 계정인지, 무엇을 만들지, 어디에 둘지, 하지 말아야 할 일은 무엇인지 적습니다. 돈·고객 정보·로그인 정보·파일을 건드리는 일이라면 지켜야 할 조건을 덧붙입니다.
@ 로 맥락 붙이기입력창에서 @ 를 쓰면 쓸 수 있는 맥락(context — 에이전트가 참고할 자료)을 붙일 수 있습니다. 이 실습은 폴더 이름을 글로 적었으므로 @ 없이 진행합니다.

확인: 입력창에 요청문이 들어가 있고, 자료(Downloads 의 영수증 PDF) · 결과(경비 보고서 표) · 칸 네 가지가 빠지지 않았습니다.

3단계 · 필요하면 권한과 작업 폴더 고르기

새 작업에는 모드 · 권한 · 작업 폴더 · 모델을 고르는 조절 항목이 있습니다. 원문은 "작업에 파일이 필요하면 권한 모드와 작업 폴더를 고르라"고 안내합니다. 이번 작업은 영수증 파일을 읽고 표를 만들므로 이 두 가지를 확인합니다.

조절 항목뜻

  2. 권한 모드 확인하기새 작업의 기본값은 Guard 입니다. 연습에서는 범위가 가장 넓은 Full access 로 바꾸지 말고, 허락한 폴더 안에서만 일하는 Guard 그대로 두는 쪽이 무난합니다(이 활용편의 권장).

확인: 작업 폴더가 영수증이 있는 폴더로, 권한 모드가 내가 고른 것으로 되어 있습니다.

4단계 · 보내고, 진행을 지켜보기

  1. 작업 보내기요청문을 보냅니다(Send the task).
  2. 진행 지켜보기작업 중에 Aside 는 사이트를 둘러보고, 웹을 검색하고, 파일을 쓰고, 방문 기록을 찾아보고, 승인을 요청하고, 허용된 자동 입력으로 로그인할 수 있습니다. 한 번에 끝나지 않고 여러 단계를 이어서 진행합니다.
  3. 물어보면 답하기작업은 도중에 멈춰서 내 입력을 기다리거나 승인을 구할 수 있습니다. 그때는 무엇을 묻는지 읽고 답합니다.

확인: 작업이 시작되어 진행 내용이 보입니다. 질문이나 승인 요청이 나왔다면 답했습니다.

5단계 · 만든 파일 확인하기

  1. 작업 상세 페이지 열기작업 상세 페이지(task detail page — 작업 하나의 진행과 결과를 보는 화면)에는 그 작업이 만들거나 바꾼 파일이 나옵니다. 이 페이지를 여는 위치는 원문에 적혀 있지 않으니, 화면에서 방금 보낸 작업을 찾아 엽니다.
  2. 경비 보고서 파일 찾기목록에서 새로 만들어진 표 파일을 찾습니다.
  3. 내용 살펴보기Aside 는 작업의 파일 가운데 지원되는 이미지 · PDF · HTML · 텍스트 파일을 미리 보여 주고, 파일 정보도 보여 줍니다.

확인: 작업이 만든 파일 목록에 경비 보고서 파일이 있습니다. 자세한 점검은 아래 잘 됐는지 확인에서 합니다.

잘 됐는지 확인

  • 작업 상세 페이지의 파일 목록에 새 경비 보고서 파일이 있습니다.
  • 표에 날짜 · 가맹점 · 합계 · 결제 수단 네 칸이 모두 있습니다.
  • 영수증 한 장을 골라, 표의 그 줄과 원래 영수증의 날짜·합계를 내 눈으로 맞춰 봤습니다. 에이전트의 결과도 사람이 한 번 대조하는 습관을 들입니다.
  • Downloads 에 넣어 둔 영수증 수와 표의 줄 수가 맞는지 세어 봤습니다.

Sign in to Rippling, get my paystubs for this month, and save the PDFs to Downloads. Ask if Rippling needs MFA or a verification code.

바꿔 해 보기 ② 답장 초안까지만 쓰게 하기 (Clay meeting outreach)
요청문 
Clay 에서 NY Tech Week 에 오는 영업 담당 부사장(Sales VP)들을 찾고, 내 캘린더에서 다음 주에 비는 시간을 확인한 다음, 미팅 답장 초안을 써 줘. 보내기 전에 멈춰.

원문(영어)

Find Sales VPs in Clay who are coming to NY Tech Week, check my calendar for open times next week, and draft meeting replies. Stop before sending.

  • 다음 실습 — 실습 2: 보고 있는 페이지를 사이드 패널로 맡기기. 지금 보는 페이지가 일의 바탕일 때 쓰는 방법입니다.
  • Ask AI 와 단축키를 더 알고 싶다면 완전 가이드 2장 브라우저로 쓰기.
  • 작업 조절 항목과 좋은 요청문 쓰는 법은 완전 가이드 3장 작업 맡기기.

한눈에 정리
  • 새 탭 입력창에는 Search 와 Ask AI 두 모드가 있습니다. 일을 맡길 때는 Ask AI 를 고르거나 Cmd/Ctrl+E 를 누릅니다.
  • 요청문에는 쓸 자료 · 원하는 결과 · 넣을 항목을 적습니다. "Handle my billing." 같은 막연한 요청은 피합니다.
  • 파일을 다루는 작업이면 권한 모드(Read only · Guard · Full access)와 작업 폴더를 고른 뒤 보냅니다.
  • 작업은 여러 단계를 이어 가다가 내 입력이나 승인을 기다리며 멈출 수 있습니다.
  • 작업이 만든 파일은 작업 상세 페이지에서 확인하고, 영수증과 표를 직접 대조합니다.

SCENARIO 2

보고 있는 페이지를 사이드 패널로 맡기기 — 계약 페이지에서 날짜 뽑기

지금 보고 있는 페이지가 곧 일의 바탕일 때는 사이드 패널(side panel — 보고 있는 페이지 옆에 여는 창)에서 시작합니다. 페이지가 작업에 저절로 붙으므로 "이 페이지에서 찾아 줘"라고만 쓰면 됩니다. 계약 내용이 적힌 페이지에서 갱신일과 해지 기한을 뽑아 표로 받아 봅니다.

이 실습으로 할 수 있게 되는 것
  • 일을 맡길 페이지를 연 상태에서 사이드 패널로 작업(에이전트에게 맡기는 일 하나)을 시작합니다.
  • 페이지 첨부가 붙어 있는지 확인하고, 필요 없으면 뗍니다.
  • "이 페이지에서 무엇을 찾아 어떤 모양으로 달라"는 요청문(prompt — 에이전트에게 써 보내는 글)을 씁니다.
  • 새 탭에서 시작할 일과 사이드 패널에서 시작할 일을 구분합니다.
처음이라면 이 순서로

준비물에서 연습할 페이지를 정하고 → 따라 하기 다섯 단계를 진행한 뒤 → 잘 됐는지 확인합니다. 답이 페이지와 상관없이 나오면 막히면을 봅니다.

준비물

  • 시작 전 준비를 마쳤습니다. 실습 1을 해 봤다면 더 쉽습니다.
  • 계약 내용이 적힌 웹 페이지 하나 — 구독 서비스의 계약·약관 페이지처럼 갱신일이나 해지 조건이 적힌 페이지를 Aside 에서 열 수 있어야 합니다. 로그인이 필요한 페이지라면 먼저 로그인해 둡니다.
  • 그 페이지에서 찾고 싶은 것 — 이 실습은 원문 예시대로 갱신일 · 해지 기한 · 청구 담당자 · 통지 기간 네 가지입니다.

먼저 어디서 시작할지부터 정합니다. 원문은 이렇게 나눕니다 — 여러 사이트·계정·파일에 걸친 일은 작업 페이지(task page)(작업을 새로 적어 보내는 화면)에서, 지금 보는 페이지가 작업의 맥락(context — 에이전트가 참고할 바탕 자료)이 되어야 할 때는 사이드 패널에서.

비유로 보면동료에게 서류를 펼쳐 보이며 "여기서 날짜만 찾아 줘"라고 부탁하는 것과 같습니다. 서류를 이미 같이 보고 있으니 어느 서류인지 길게 설명할 필요가 없습니다. 사이드 패널의 페이지 첨부가 그 "펼쳐 보인 서류" 역할을 합니다.

따라 하기

1단계 · 일을 맡길 페이지 열기

  1. 계약 페이지 열기Aside 에서 준비한 계약 페이지를 엽니다.
  2. 이 페이지가 맞는지 보기원문은 "작업의 기준이 될 페이지에서 사이드 패널을 열라"고 안내합니다. 다른 탭을 보고 있는 상태로 다음 단계로 가지 않도록, 맡길 페이지가 화면에 보이는지 확인합니다.

확인: 화면에 계약 페이지가 열려 있습니다.

2단계 · Aside 사이드 패널 열기

  1. 사이드 패널 열기그 페이지를 보는 채로 Aside 사이드 패널을 엽니다. 패널을 여는 버튼이나 단축키는 이 실습의 원문(사이드 패널 문서)에 적혀 있지 않으니, 화면에서 찾아 엽니다.

확인: 페이지 옆에 사이드 패널이 열리고, 요청문을 쓰는 입력 칸이 보입니다.

3단계 · 페이지 첨부 확인하기

사이드 패널은 지금 보는 페이지를 새 작업에 붙여 줍니다. 이것이 페이지 첨부(page attachment)이고, 첨부에는 그 페이지의 제목과 호스트 이름(hostname — 주소에서 사이트를 가리키는 부분. 예: example.com)이 표시됩니다.

  1. 첨부에 적힌 제목과 호스트 이름 읽기내가 맡기려는 계약 페이지가 맞는지 봅니다.
  2. 첨부를 그대로 두기Aside 가 이 페이지를 읽게 하려면 첨부를 남겨 둡니다. 이번 실습은 남겨 둡니다.
첨부를 떼는 경우이 페이지와 상관없는 일을 시작하려면 첨부를 지웁니다. 그러면 Aside 는 그 페이지 없이 작업을 시작합니다.

확인: 첨부에 계약 페이지의 제목과 호스트 이름이 보입니다.

4단계 · 요청문 쓰기

아래는 원문의 「Extract contract dates」(계약 날짜 뽑기) 예시를 한국어로 옮긴 문장입니다. 원문 예시는 영어이므로 영어 문장도 함께 싣습니다. 복사해서 사이드 패널 입력 칸에 붙여 넣습니다.

보낼 요청문 
이 계약 페이지에서 갱신일, 해지 기한, 청구 담당자, 통지 기간을 찾아 줘. 날짜는 표로 정리하고, 앞으로 60일 안에 기한이 오는 것은 표시해 줘.

원문(영어)

Use this contract page to find the renewal date, cancellation deadline, billing owner, and notice period. Put the dates in a table and flag anything due in the next 60 days.

이 요청문은 세 가지를 말합니다 — 어디서(이 계약 페이지), 무엇을(네 가지 항목), 어떤 모양으로(날짜는 표, 60일 안에 오는 것은 표시). 파일을 다루지 않는 일이라 권한 모드와 작업 폴더는 따로 고르지 않습니다(원문은 "작업에 파일이 필요하면" 고르라고 안내합니다).

쓰다 만 요청문은 그 탭에 남습니다Aside 는 사이드 패널의 초안(draft — 아직 보내지 않은 글)을 페이지 맥락별로 저장합니다. 페이지를 떠났다가 나중에 돌아와도, 초안은 쓰기 시작한 탭에 묶여 남아 있을 수 있습니다.

확인: 입력 칸에 요청문이 있고, 3단계에서 본 페이지 첨부가 그대로 붙어 있습니다.

5단계 · 보내고 답 확인하기

  1. 보내기요청문을 보냅니다(Send it).
  2. 답 읽기에이전트(사람 대신 브라우저를 조작해 일하는 AI)가 페이지를 읽고 답합니다. 답이 어떤 모양으로 나오는지는 원문에 그려져 있지 않습니다. 요청한 대로 날짜가 표로 정리됐는지, 60일 안에 오는 기한에 표시가 붙었는지 봅니다.

확인: 답에 네 가지 항목이 들어 있습니다. 자세한 점검은 아래 잘 됐는지 확인에서 합니다.

잘 됐는지 확인

  • 보내기 전, 첨부에 계약 페이지의 제목과 호스트 이름이 보였습니다.
  • 답에 갱신일 · 해지 기한 · 청구 담당자 · 통지 기간 네 가지가 모두 있습니다. 페이지에 실제로 적혀 있지 않은 항목이 있는지도 함께 봅니다.
  • 날짜가 표로 정리되어 있고, 60일 안에 오는 기한에는 표시가 있습니다.
  • 표의 날짜 하나를 골라 계약 페이지의 원래 문장과 내 눈으로 맞춰 봤습니다. 계약 날짜처럼 틀리면 곤란한 값은 꼭 한 번 대조합니다.

SCENARIO 3

글자·그림을 골라 바로 묻기 — 선택·올가미 단축 쓰고 만들기

페이지 전체를 맡길 것까지는 없고 "이 문단만 요약해 줘" 정도의 짧은 질문일 때는 선택 단축(selection shortcuts — 글자나 화면 한 부분을 고르면 바로 쓸 수 있는 빠른 동작)을 씁니다. 처음부터 들어 있는 단축 네 개를 써 보고, 자주 하는 질문을 내 단축으로 만들어 봅니다.

이 실습으로 할 수 있게 되는 것
  • 글자를 골라 Summarize(요약) · Translate(번역) 단축을 씁니다.
  • 올가미 선택(Lasso — 화면 한 부분을 둘러서 고르기)으로 Copy code(코드 복사) · Search image(그림 검색) 단축을 씁니다.
  • Settings → Lasso(설정 → 올가미)에서 단축을 끄고, 순서를 바꾸고, 고치고, 지우고, 새로 만듭니다.
  • {text} 가 들어간 틀로 "조항 요약" 같은 내 단축을 만들어 씁니다.
처음이라면 이 순서로

준비물을 갖추고 → 따라 하기에서 1·2단계(기본 단축 써 보기)만 먼저 해도 됩니다. 3~5단계는 내 단축을 만드는 연습입니다. 끝나면 잘 됐는지 확인하고, 단축이 보이지 않으면 막히면을 봅니다.

준비물

  • 시작 전 준비를 마쳤습니다.
  • 글이 있는 웹 페이지 하나 — 약관이나 사내 규정처럼 조항이 나뉘어 있는 페이지면 4·5단계 연습에 좋습니다.
  • 그림이나 코드가 있는 웹 페이지 하나 — 2단계 올가미 연습용입니다. 없다면 2단계는 읽기만 하고 넘어가도 됩니다.
  • 선택 단축은 처음부터 켜져 있으므로 따로 켤 것은 없습니다.

  2. Copy code 또는 Search image 고르기올가미 선택에 기본으로 들어 있는 단축은 Copy code(코드 복사)와 Search image(그림 검색) 두 가지입니다.

SCENARIO 4

로그인 뒤에 있는 자료 받아 오기

급여명세서처럼 로그인해야 보이는 자료를 에이전트(agent — 사람 대신 브라우저를 조작해 일하는 AI)에게 받아 오게 합니다. 로그인은 Aside Vault(Aside 의 비밀번호 금고)가 자동 입력(autofill — 저장해 둔 아이디·비밀번호를 로그인 칸에 대신 채우는 일)으로 처리하고, 에이전트는 비밀번호 값을 받지 않습니다.

이 실습으로 할 수 있게 되는 것
  • Aside Vault 에 저장한 로그인으로 에이전트가 로그인 화면을 지나가게 합니다.
  • 에이전트가 저장된 로그인을 써도 되는 때를 세 가지 정책 중에서 고릅니다.
  • 사이트가 추가 인증을 요구해 작업(task — 에이전트에게 맡기는 일 하나)이 나를 기다릴 때 무엇을 하면 되는지 압니다.
처음이라면 이 순서로

준비물을 확인하고 → 따라 하기 4단계를 진행한 뒤 → 잘 됐는지 확인합니다. 자동 입력이 나오지 않거나 작업이 멈춰 있으면 막히면에서 같은 증상을 찾으세요.

준비물

  • 실습 1을 마친 상태. 새 탭의 Ask AI(새 탭 입력창의 「AI 에게 맡기기」 모드)로 작업을 보내 본 적이 있어야 합니다.
  • 받아 올 자료가 있는 사이트의 로그인이 Aside Vault 에 저장돼 있음. 원문 예시는 Rippling(원문 예시 속 서비스 — 내 회사에서 급여명세서를 받는 사이트로 바꿔 읽으세요)입니다. 쓰던 비밀번호 관리자에서 옮겨 올 수도 있습니다(아래 접힌 상자).
  • 작업을 평소 모드(Default)로 보낼 것. 시크릿(Incognito) 작업에서는 에이전트가 비밀번호 관리자를 쓸 수 없습니다.
  • 추가 인증에 쓸 수단을 곁에 둘 것. 사이트가 MFA(다단계 인증 — 비밀번호 말고 한 번 더 확인하는 절차)나 인증 코드를 요구하면 그 단계는 내가 직접 해야 합니다.
저장된 로그인이 없다면 — 쓰던 비밀번호 관리자에서 가져오기

Settings → Passwords → Import(설정 → 비밀번호 → 가져오기)에서 가져옵니다. 가져올 수 있는 곳은 1Password · Apple Passwords · Bitwarden · Chrome · Dashlane · Edge · Firefox · LastPass CSV 이고, 그 밖에는 일반 CSV 파일로 가져옵니다.

  1. 쓰던 비밀번호 관리자에서 비밀번호를 내보냅니다내보낸 파일이 하나 생깁니다.
  2. Aside 의 비밀번호 설정을 엽니다Settings → Passwords.
  3. Import 를 고릅니다
  4. 가져올 곳(source)을 고릅니다
  5. 내보낸 파일을 고릅니다가져오기 화면이 그 관리자 전용 절차를 안내하면 화면 안내를 따릅니다.
  6. 결과를 살펴봅니다가져온 뒤에는, 백업이 더 필요할 때만 내보낸 파일을 남겨 둡니다.

4단계 · 로그인 화면 지나가기

작업이 로그인 화면에 닿으면 Aside 가 대상 주소(URL)와 비밀번호 접근 설정을 확인하고, 허용된 로그인이 있으면 그 화면에 자동으로 채웁니다. 에이전트는 "로그인하기"라는 동작만 쓸 뿐, 비밀번호 값 자체는 받지 않습니다.

어떤 사이트는 그래도 사람이 해야 하는 단계가 남습니다. 사이트가 MFA, 패스키(passkey — 비밀번호 대신 내 기기로 인증하는 방식) 승인, CAPTCHA(사람인지 확인하는 문제), 본인 확인을 요구하면 화면에 보이는 그 단계를 내가 마치고 작업이 이어 가게 둡니다.

SCENARIO 5

“보내기 전에 멈춰” — 초안까지만 시키기

답장·게시·설정 변경처럼 내 이름으로 밖에 나가는 일은, 에이전트(agent — 사람 대신 브라우저를 조작해 일하는 AI)에게 초안까지만 쓰게 하고 보내기 직전에 멈추게 합니다. 요청문(prompt — 에이전트에게 써 보내는 글) 끝에 “게시하기 전에 멈춰” 한 줄을 적는 것이 이 실습의 핵심입니다.

이 실습으로 할 수 있게 되는 것
  • 보고 있는 페이지를 사이드 패널(side panel — 보고 있는 페이지 옆에 여는 창)로 맡기면서, 멈출 곳을 요청문에 적습니다.
  • 권한 모드 세 가지(Read only · Guard · Full access)의 차이를 알고 고릅니다.
  • 작업(task — 에이전트에게 맡기는 일 하나)이 도는 중에 후속 메시지(Queue · Steer)로 방향을 고치거나 멈추게 합니다.
처음이라면 이 순서로

준비물을 확인하고 → 따라 하기 5단계를 진행한 뒤 → 잘 됐는지 확인합니다. 에이전트가 멈추지 않거나 작업이 나를 기다리면 막히면을 봅니다.

준비물

  • 실습 2를 마친 상태. 보고 있는 페이지에서 사이드 패널을 열어 작업을 보내 본 적이 있어야 합니다.
  • 답장 초안이 필요한 페이지 하나. 원문 예시는 고객 문의 스레드(한 문의에 오간 글이 이어진 묶음)와, 거기에 연결된 고객 계정 페이지입니다.
  • 로그인이 필요한 사이트라면 실습 4의 준비. 저장된 로그인으로 에이전트가 로그인 화면을 지나갑니다.

2단계 · 권한 모드 고르기

새 작업에는 모드, 권한, 작업 폴더, 모델을 고르는 조절 항목이 있습니다. 이 가운데 권한 모드는 에이전트가 내 컴퓨터의 파일을 어디까지 읽고 바꿀 수 있는지를 정합니다. 새 작업의 기본값은 Guard 입니다.

모드하는 일

Guard(기본값)허락한 폴더 안에서 일하고, 다른 폴더에 손대기 전에는 먼저 물어봅니다.

답장 초안만 받을 이번 실습에서는 Read only 나 기본값 Guard 를 고릅니다. 고르는 칸의 위치는 화면 안내를 따릅니다.

원문이 설명하는 권한 모드는 내 컴퓨터의 파일에 관한 범위입니다. 웹사이트에서 답장을 게시하는 일까지 막아 준다고는 적혀 있지 않습니다. 그래서 멈출 곳은 다음 단계의 요청문에 직접 적습니다.

원문은 결제·게시·메시지 보내기 같은 민감한 행동은 작업이 승인을 요청할 때 내 확인을 기다려야 한다고 적습니다. 요청문의 “멈춰”와 이 확인이 함께 있는 셈입니다. 그래도 멈출 곳을 내 말로 적어 두는 쪽이 원문 예시들의 공통된 방식입니다.

5단계 · 도는 중에 고치거나 멈추게 하기

작업이 도는 중에 새 메시지를 보내면 두 방식 중 하나로 반영됩니다. 어느 쪽으로 할지는 Settings → Agents → Chat(설정 → 에이전트 → 채팅)에서 고릅니다.

방식하는 일쓸 때
Queue(줄 세우기)새 메시지를 보관해 두었다가 지금 실행이 끝난 뒤 반영합니다.하던 길을 끝까지 가게 두어도 될 때
Steer(방향 틀기)새 메시지를 지금 실행 속으로 보내 에이전트가 바로 고치게 합니다.지금 바로잡아야 할 때 — 다른 사이트를 쓰게 하거나 하던 행동을 멈추게 할 때

SCENARIO 6

여러 탭을 나란히 두고 일 시키기

분할 탭(split tabs — 한 창 안에 두 페이지를 나란히 띄우는 기능)을 쓰면 Aside 가 일하는 동안 두 페이지를 한눈에 볼 수 있습니다. 자료와 옮겨 적을 곳을 나란히 두거나, 작업이 도는 모습을 옆에서 지켜봅니다.

이 실습으로 할 수 있게 되는 것
  • 단축키로 탭을 둘로 나눕니다.
  • 자료 문서를 옆에 띄워 둔 채, 에이전트(agent — 사람 대신 브라우저를 조작해 일하는 AI)가 양식에 옮겨 적은 내용을 눈으로 대조합니다.
  • 작업(task — 에이전트에게 맡기는 일 하나) 기록과 에이전트가 조작하는 페이지를 나란히 두고 지켜보다가, 엇나가면 바로잡습니다.
처음이라면 이 순서로

준비물을 확인하고 → 따라 하기의 1단계로 탭을 나눈 뒤 2단계나 3단계 중 하나를 골라 진행하고 → 잘 됐는지 확인합니다. 단축키가 듣지 않거나 에이전트가 다른 페이지를 읽으면 막히면을 봅니다.

준비물

  • 실습 1과 실습 2를 마친 상태. 새 탭의 Ask AI(새 탭 입력창의 「AI 에게 맡기기」 모드)와 사이드 패널(side panel — 보고 있는 페이지 옆에 여는 창)로 작업을 보내 본 적이 있어야 합니다.
  • 나란히 둘 페이지 두 개. 예: 계약 페이지(자료)와 그 내용을 옮겨 적을 양식 페이지.
  • 멈출 곳을 적는 습관. 양식을 제출하는 일은 실습 5처럼 요청문(prompt — 에이전트에게 써 보내는 글)에 “제출하기 전에 멈춰”를 적어 막아 둡니다.

원문은 분할 탭이 잘 맞는 쓰임을 네 가지로 듭니다. 이 실습은 그중 ②와 ④를 따라 합니다.

SCENARIO 7

매주 반복되는 일을 루틴으로

매주 같은 요약을 만들거나, 같은 채팅을 며칠 뒤에 다시 이어 가야 한다면 루틴(routine — 반복 작업 예약)으로 걸어 둡니다. 작업(task — 에이전트에게 맡기는 일 하나)을 매번 손으로 시작하지 않아도 Aside 가 되풀이해 돌립니다.

이 실습으로 할 수 있게 되는 것
  • 루틴 두 종류(Cron routine · Heartbeat routine)의 차이를 알고 내 일에 맞는 쪽을 고릅니다.
  • Settings → Routines(설정 → 루틴)에서 루틴을 만들고, 지금 한 번 돌려 확인합니다.
  • Aside 가 찾아 준 루틴 제안을 살펴보고 고쳐서 켭니다.
  • 루틴이 돌지 않거나 사라지는 세 가지 경우를 미리 압니다.
처음이라면 이 순서로

준비물을 확인하고 → 따라 하기 5단계와 그 아래 주의 세 가지를 읽은 뒤 → 잘 됐는지 확인합니다. 루틴이 돌지 않거나 보이지 않으면 막히면을 봅니다.

준비물

  • 실습 1을 마친 상태. 작업을 보내고 결과를 받아 본 적이 있어야 합니다.
  • 되풀이할 일 하나. 원문의 직무별 글은 월요일 대시보드(여러 수치를 한 화면에 모아 보여 주는 페이지) 요약, 월말 청구서 모으기, 갱신 확인, 거래처 상태 점검처럼 매번 같은 자료를 보는 일을 후보로 듭니다.
  • 요금제에 따른 한도 확인. Free 요금제는 켜 둔(active) 루틴을 3개까지 둘 수 있고, Pro 는 한도가 없습니다(2026-11-09 수집 기준).
  • 루틴이 돌 시각에 켜져 있을 컴퓨터. 컴퓨터가 깨어 있고, 인터넷에 연결돼 있고, Aside 가 실행 중이어야 합니다.
  • (갈래 나만) 이어 갈 채팅(chat — 작업의 대화 기록) 하나.

루틴을 걸어 두기 전에 — 주의 세 가지

① 컴퓨터가 켜져 있어야 돕니다. 루틴은 내 컴퓨터에서 돕니다. 컴퓨터가 잠들거나 꺼지면 돌지 않고, 유료 요금제라고 해서 계속 돌려 주지 않습니다. 컴퓨터를 깨어 있게, 인터넷에 연결된 채로, Aside 를 실행한 채로 둡니다. 클라우드에서 대신 돌려 주는 기능(Cloud handoff)은 아직 준비 중(Coming Soon)이며 Pro 구독으로 켜지지 않습니다.

② 채팅을 지우면 그 채팅이 만든 루틴도 지워집니다. Delete(삭제)는 되돌릴 수 없고, 그 채팅이 만든 루틴을 함께 지우며 돌던 실행도 멈춥니다. 채팅과 루틴을 남기려면 Archive(보관)를 씁니다. 다만 보관한 채팅의 루틴은 Settings → Archived chats(설정 → 보관한 채팅)에서 Unarchive 로 되살릴 때까지 돌지 않습니다.

③ Free 요금제는 켜 둔 루틴이 3개까지입니다. Pro 는 한도가 없습니다(2026-11-09 수집 기준).

  • 다음에 돌 시각에 컴퓨터가 깨어 있고, 인터넷에 연결돼 있고, Aside 가 실행 중이도록 해 두었습니다.

SCENARIO 8

출처가 필요한 조사 — Ultrabrowse (선택 · Pro 요금제)

“근거가 어디에 적혀 있는지”까지 받아야 하는 조사가 있습니다. 여러 자료를 오가며 견줘야 하고, 답마다 출처가 붙어야 하는 일입니다. 이런 일은 보통 작업 대신 Ultrabrowse(자료를 많이 찾아야 하는 깊은 조사용 선택지)를 골라 맡깁니다. 이 실습에서는 원문 예시인 “출장 경비 규정 검토”를 그대로 따라 합니다.

선택 실습 — Pro 요금제가 필요

Ultrabrowse 는 Pro 요금제부터 쓸 수 있습니다(Max 는 Pro 의 모든 것을 포함합니다). Free 요금제에서는 고르려고 하면 Pro 로 올리라는 안내가 보입니다. Free 요금제라면 1단계의 고르는 기준만 읽고 넘어가도 됩니다.

이 실습으로 할 수 있게 되는 것
  • 보통 작업으로 충분한 일과 Ultrabrowse 가 어울리는 일을 가릅니다.
  • 모델 선택기의 Reasoning 아래에서 Ultrabrowse 를 골라 조사를 맡깁니다.
  • 요청문에 “근거로 쓴 곳을 밝혀 줘”를 적어, 답의 근거를 내 눈으로 맞춰 봅니다.
  • 이 작업에 크레딧이 얼마나 들었는지 사용 내역에서 확인합니다.
처음이라면 이것만

준비물에서 요금제와 자료를 확인한 뒤 따라 하기의 다섯 단계를 차례로 진행합니다. Ultrabrowse 가 보이지 않거나 답에 출처가 빠졌다면 막히면에서 같은 증상을 찾습니다.

준비물

  • Pro 또는 Max 요금제. 지금 요금제는 Settings → Plan & Usage(설정 → 요금제와 사용량)에서 봅니다.
  • 남은 크레딧(credits — 요금제가 매달 주는 사용량). 같은 화면의 Credits 에 남은 비율, 다시 채워지는 날, 요금제의 한 달 크레딧 양이 나옵니다.
  • 검토할 자료 두 가지 — 출장 경비 규정과 영수증 스프레드시트. 각각 어느 사이트 또는 어느 파일에 있는지 알아 둡니다. 요청문(prompt — Aside 의 AI 에게 써 보내는 글)에 그 이름을 적을 것입니다.
  • 실습 1을 마쳐 새 작업(task — Aside 에게 맡기는 일 하나)을 보낼 줄 아는 상태.
완료 기준

Ultrabrowse 로 보낸 작업의 답에 “근거로 쓴 규정 조항”이 적혀 있고, 그 조항을 내가 직접 열어 맞춰 보았으며, 사용 내역에서 이 작업의 줄을 찾았다면 완료입니다.

회사 자료로 연습하기가 부담스럽다면 바꿔 해 보기의 예시처럼 공개된 웹 자료를 조사하는 일로 시작해도 됩니다.

1단계 · 이 일이 Ultrabrowse 에 어울리는지 가르기

Ultrabrowse 는 자료를 많이 찾아야 하거나, 계획을 더 세워야 하거나, 여러 페이지를 꼼꼼히 견줘야 하는 일에 씁니다. 한 페이지에 대한 질문이나 기본 검색은 보통 작업으로 충분합니다.

이 실습의 “출장 경비 규정 검토”는 규정 문서와 영수증 목록을 서로 견주고, 판단마다 근거 조항을 대야 하므로 오른쪽에 해당합니다.

확인: 내가 맡길 일이 오른쪽 네 가지 가운데 하나와 닮았습니다. 닮지 않았다면 보통 작업으로 보내는 편이 맞습니다.

2단계 · 모델 선택기에서 Ultrabrowse 고르기

  1. 새 작업을 시작합니다실습 1에서 한 것과 같습니다. 새 작업에는 모드·권한·작업 폴더·모델을 정하는 조절 항목이 있습니다.
  2. 모델 선택기를 엽니다모델 선택기(model selector)는 이 작업에 쓸 AI 모델과 속도를 고르는 곳입니다. 화면 어디에 있는지는 원문에 적혀 있지 않으니, 새 작업 화면에서 모델을 고르는 항목을 찾습니다.
  3. Reasoning 아래에서 Ultrabrowse 를 고릅니다내 계정이 Ultrabrowse 를 쓸 수 있으면 Reasoning(추론) 묶음 아래에 Ultrabrowse 가 나옵니다.

확인: 모델 선택기에서 Ultrabrowse 가 골라져 있습니다. Pro 안내가 보인다면 지금 계정은 Free 요금제입니다 — 막히면의 첫 줄을 봅니다.

SCENARIO 9

기억 확인·고치기와 흔적 지우기 (선택)

Aside 는 방문 기록·채팅·작업에서 얻은 맥락(context — 일을 할 때 참고할 앞뒤 사정과 자료)을 다시 쓰려고 기억(Memory — Aside 가 다음에 다시 쓰려고 간직해 두는 내용)을 만듭니다. 편리한 만큼, 무엇을 기억하는지 내가 보고 고칠 수 있어야 하고 남기고 싶지 않은 흔적은 지울 수 있어야 합니다. 이 실습에서는 두 갈래를 차례로 해 봅니다 — 기억을 살펴보고 고치기, 그리고 브라우저에 쌓인 흔적 지우기.

선택 실습

기억이나 방문 기록을 손볼 일이 생겼을 때 해도 되는 실습입니다. 두 갈래는 서로 이어지지 않으므로 필요한 쪽만 해도 됩니다.

이 실습으로 할 수 있게 되는 것
  • Aside 가 기억하는 내용을 살펴보고, 틀린 것을 고치고, 바뀐 내역을 되짚어 봅니다.
  • 기억을 켜고 끄며, 켜 두었다면 보관 기간 세 가지 가운데 하나를 고릅니다.
  • 방문 기록·쿠키 같은 자료 여섯 가지를 기간을 골라 지웁니다.
  • “기억 끄기”와 “방문 기록 지우기”가 서로 다른 일임을 구분합니다.
처음이라면 이것만

준비물에서 두 갈래의 차이를 그림으로 본 뒤 따라 하기에서 필요한 갈래를 진행합니다. 기억을 껐는데 예전 기억이 남아 있는 것처럼 뜻대로 되지 않으면 막히면에서 같은 증상을 찾습니다.

준비물

  • Aside 에서 Settings(설정)를 열 수 있는 상태.
  • 가 갈래(기억) — Aside 로 채팅이나 작업을 몇 번 해 본 상태면 살펴볼 것이 있습니다. 기억은 채팅과 작업 활동에서 만들어집니다.
  • 나 갈래(흔적 지우기) — 무엇을, 어느 기간만큼 지울지 미리 정합니다. 원문은 지운 자료를 되살리는 방법을 적고 있지 않으므로, 되살릴 수 없다고 생각하고 고릅니다.
완료 기준

가 갈래는 저장된 기억을 한 번 살펴보고 보관 기간을 내가 고른 값으로 맞추면 완료입니다. 나 갈래는 고른 기간의 방문 기록이 지워진 것을 확인하면 완료입니다.

먼저 두 갈래가 어떻게 다른지 봅니다. 메뉴도 다르고 하는 일도 다릅니다.

비유로 보면

기억을 끄는 것은 수첩에 새로 적지 않기로 하는 것이고, 방문 기록을 지우는 것은 책상 서랍에 쌓인 영수증을 버리는 것입니다. 수첩에 그만 적는다고 서랍이 저절로 비지 않고, 서랍을 비우는 메뉴에는 수첩을 고치는 항목이 없습니다. 원문도 두 일을 다른 메뉴에서 따로 설명하며, 한쪽을 하면 다른 쪽도 된다고 적지 않습니다. 그러니 둘 다 정리하려면 두 곳을 각각 봅니다.

SCENARIO 10

작업이 멈추거나 엇나갈 때

작업(task — Aside 에게 맡기는 일 하나)이 멈춰 있다고 해서 고장은 아닙니다. Aside 의 작업은 여러 단계를 이어 가다가 입력을 기다리며 멈추거나, 승인을 요청하거나, 기다린 뒤 다시 이어 갈 수 있습니다. 이 실습에서는 흔한 여섯 가지 상황마다 무엇을 열고 무엇을 확인하는지 원문 순서 그대로 따라 합니다.

이 실습으로 할 수 있게 되는 것
  • 멈춘 작업이 나에게 무엇을 바라는지 찾아 승인하거나, 거절하거나, 답합니다.
  • 엇나간 작업을 후속 메시지로 바로잡고, Queue 와 Steer 를 가려 씁니다.
  • 비밀번호 자동 입력이 안 뜨거나 브라우저 가져오기가 실패할 때 점검할 것을 순서대로 확인합니다.
  • 그래도 풀리지 않을 때 필요한 정보 일곱 가지를 갖춰 신고합니다.

  • 적어 둘 메모장. 문제가 생긴 대략의 시각과 화면에 보이는 오류 문구를 그때 적어 두면 ⑥ 신고가 쉬워집니다.
완료 기준

내 증상의 단계를 끝까지 밟아 작업이 다시 이어졌거나, 풀리지 않아 일곱 가지 정보를 갖춰 신고를 보냈다면 완료입니다. 지금 문제가 없다면 ① 과 ② 만 읽어 두어도 충분합니다.

따라 하기

1작업이 나를 기다립니다

  1. 작업을 엽니다기다리고 있는 그 작업입니다. 작업 목록이 화면 어디에 있는지는 원문에 적혀 있지 않으니, 화면에서 그 작업을 찾아 엽니다.
  2. 입력 요청이나 승인 요청을 찾습니다Aside 가 나에게 묻거나 허락을 구하는 부분입니다.
  3. 요청한 행동을 살펴봅니다무엇을 하려는지, 내가 바란 일이 맞는지 읽습니다.
  4. 승인하거나, 거절하거나, 답합니다내키지 않으면 거절해도 됩니다.
  5. 화면에 이어 하기(resume) 동작이 보이면 작업을 이어 갑니다보이지 않으면 이 단계는 건너뜁니다.

요청이 어디에 나타나는지는 종류에 따라 다릅니다.

작업에는 승인 대기(waiting for approval), 답 대기(waiting for an answer), 오류(errored), 끝남(finished) 같은 상태가 보일 수 있습니다.

로그인 화면에서 멈췄다면

Aside 는 로그인 화면에 닿으면 허용된 저장 로그인 정보를 자동 입력(autofill — 저장해 둔 아이디·비밀번호를 칸에 대신 채워 주는 기능)으로 넣을 수 있습니다. 사이트가 MFA(다단계 인증 — 비밀번호 말고 코드 등을 한 번 더 확인하는 절차), 패스키(passkey — 비밀번호 대신 쓰는 로그인 수단) 승인, CAPTCHA(사람인지 확인하는 문제), 본인 확인을 요구하면 화면에 보이는 그 단계를 내가 직접 마치거나 Aside 의 요청에 답한 뒤 작업을 이어 갑니다.

확인: 요청에 답했고, 작업이 더는 나를 기다리지 않습니다.

2작업이 엉뚱한 길로 갑니다

후속 메시지(follow-up)를 보내 바로잡습니다. 후속 메시지가 반영되는 방식은 두 가지이고, Settings → Agents → Chat(설정 → 에이전트 → 채팅)에서 고릅니다.

Steer (방향 틀기)Queue (줄 세우기)
새 메시지가 어떻게 되나지금 돌고 있는 실행 안으로 보내, 에이전트(사람 대신 브라우저를 조작해 일하는 AI)가 방향을 고치게 합니다.저장해 두었다가 지금 실행이 끝난 뒤 반영합니다.
이럴 때 고릅니다지금 바로 고쳐야 할 때 — 다른 사이트를 쓰게 하거나 어떤 행동을 멈추게 해야 할 때.지금 가던 길을 끝까지 가게 두어도 될 때 — 지시가 기다려도 될 때.
  1. 지금 바로 고쳐야 하는지 정합니다잘못된 곳에서 무언가를 하려 한다면 Steer, 덧붙일 주문일 뿐이라면 Queue 입니다.
  2. Settings → Agents → Chat 에서 후속 메시지 동작을 고릅니다Queue 또는 Steer.
  3. 그 작업에 후속 메시지를 보냅니다무엇을 그만할지, 대신 무엇을 할지, 무엇은 하지 말지를 적습니다.
원문 예시 — 엇나간 작업 바로잡기

“결제(billing) 페이지는 그만 써. 대신 청구서(invoices) 페이지를 쓰고, 이메일은 하나도 보내지 마.”

원문Stop using the billing page. Use the invoices page instead, and do not send any emails.

이 예시는 세 가지를 한 번에 말합니다 — 그만할 것(결제 페이지), 대신 할 것(청구서 페이지), 하지 말 것(이메일 보내기). 내 상황에 맞게 이 세 자리를 바꿔 씁니다.

확인: 작업을 열어 보면 고쳐 준 방향으로 진행하고 있습니다. 여전히 엇나간다면 더 구체적으로 다시 보냅니다.

3작업이 알림을 기다립니다

Aside 는 알림을 기다리는 동안 작업을 멈춰 둘 수 있습니다. 이때는 고칠 것이 아니라 무엇을 기다리는지를 봅니다.

  1. 작업을 엽니다지금 상태와 Aside 가 남긴 안내를 읽습니다.
  2. Aside 가 기다리는 것이 셋 가운데 무엇인지 봅니다내 답(reply), 내 승인(approval), 연결된 앱에서 일어날 일(connected app event).
  3. 답이나 승인이라면 ① 의 순서로 답합니다연결된 앱의 일을 기다리는 중이라면 작업에 적힌 Aside 의 안내를 따릅니다.

확인: 작업이 무엇을 기다리는지 알게 되었고, 내가 할 일이 있었다면 마쳤습니다.

4비밀번호 자동 입력이 뜨지 않습니다

아래 여섯 가지를 위에서부터 차례로 확인합니다. 모두 Settings → Passwords(설정 → 비밀번호)에서 봅니다.

  1. Settings → Passwords 를 엽니다비밀번호 설정 화면입니다.
  2. Use default password manager 가 켜져 있는지 봅니다Aside 가 비밀번호를 관리하게 하려는 경우에 켜져 있어야 합니다.
  3. Enable Autofill 이 켜져 있는지 봅니다자동 입력을 켜는 항목입니다.
  4. 시크릿 창이라면 Disable in incognito 를 확인합니다시크릿에서 자동 입력을 끄는 항목입니다.
  5. Excluded domains 를 확인합니다자동 입력에서 뺀 사이트 주소 목록입니다. 지금 사이트가 들어 있는지 봅니다.
  6. 지금 사이트에 보안되지 않은 사이트 자동 입력이 허용되어 있는지 봅니다보안 연결이 아닌 사이트에서의 자동 입력(insecure-site autofill)은 따로 허용 여부가 있습니다.
패스키 · MFA · 여러 단계 로그인이라면

Aside 가 저장된 로그인 정보를 먼저 채울 수 있습니다. 그다음 화면에 보이는 확인 단계는 내가 마치고, 다음 안내가 나올 때까지 기다립니다.

확인: 같은 사이트의 로그인 화면에서 자동 입력이 나옵니다. 비밀번호 설정 전체는 완전 가이드 5장 비밀번호와 로그인에 있습니다.

5브라우저 가져오기가 실패합니다

가져오기(import — 쓰던 브라우저의 자료를 Aside 로 옮겨 오는 일)가 실패하면 네 가지를 차례로 확인합니다.

  1. 자료를 가져올 쪽 브라우저의 프로필이 아직 있는지 확인합니다프로필(profile)은 그 브라우저가 쌓아 둔 내 자료 묶음입니다. 가져올 원본이 있어야 합니다.
  2. 가져오는 동안 그 브라우저를 혼자 써야 하는 경우라면, 그 브라우저를 닫습니다가져오기가 닫으라고 안내하면 닫습니다.
  3. 파일로 가져와야 하는 브라우저는 파일 가져오기를 씁니다예를 들어 Safari 는 ZIP 파일로 가져옵니다.
  4. 가져오기를 다시 시도합니다위 세 가지를 확인한 뒤입니다.

Windows 에서 Chrome 을 닫았는데도 닫으라는 안내가 계속 나오거나, 영어 오류 문구의 뜻이 궁금하면 아래 접힌 상자를 봅니다.

Windows 에서 Chrome 을 닫으라는 안내가 계속 나올 때 · 오류 문구 네 가지

Windows 에서는 Chrome 의 마지막 창을 닫아도 Chrome 이 계속 실행 중인 경우가 많아, 가져오기가 Chrome 을 닫으라고 계속 요구합니다. 작업 관리자(Task Manager)를 열어 Google Chrome 프로세스를 모두 끝낸 뒤 Try again 을 고릅니다. 작업 관리자에 하나도 보이지 않으면 Windows 를 다시 시작하고, Chrome 을 열기 전에 가져오기를 실행합니다. Chrome 에서 새 Aside 프로필을 만들다가 쿠키 복사 중에 실패할 때도 같은 방법을 씁니다.

오류 문구뜻
Browser import is unavailable in this version of Aside.이 버전의 Aside 에서는 브라우저 가져오기를 쓸 수 없습니다.
Browser import failed.브라우저 가져오기에 실패했습니다.
Please upload a ZIP fileSafari ZIP 가져오기에서 ZIP 파일을 올려 달라는 뜻입니다.
Failed to read the ZIP fileSafari ZIP 가져오기에서 ZIP 파일을 읽지 못했습니다.

확인: 다시 시도한 가져오기가 오류 문구 없이 끝났습니다.

6그래도 안 되면 신고합니다

보내는 길은 세 가지입니다. 앱 안의 두 경로와 이메일입니다.

경로여는 순서함께 담을 수 있는 것
앱 — 일반 피드백Settings 를 열고 Send feedback(피드백 보내기)을 고릅니다.화면 캡처를 넣을 수 있습니다.
앱 — 작업 피드백작업 상세 페이지를 열고, 더 보기 메뉴(more actions menu)를 연 뒤 Send feedback 을 고릅니다.그 작업의 대화 기록(transcript)과 진단 정보(diagnostics)를 넣을 수 있습니다.
이메일support@aside.com 으로 보냅니다.아래 일곱 가지를 적습니다.

특정 작업에서 생긴 문제라면 작업 피드백 쪽이 그 작업의 기록을 함께 보낼 수 있어 알맞습니다. 어느 길로 보내든 아래 일곱 가지를 챙깁니다.

신고에 넣을 것 — 7가지
  • 작업 URL 또는 작업 ID Task URL or task ID
  • 대략의 시각 Approximate time
  • 관련된 웹사이트나 앱 Website or app involved
  • 기대한 결과 Expected result
  • 실제로 일어난 결과 Actual result
  • 화면 캡처, 또는 결과 파일의 경로 — 있다면 Screenshot or artifact path, if available
  • 화면에 보인 오류 문구 Any visible error message

Aside 화면이 아니라, 보내기 전에 스스로 확인하는 점검표입니다.

확인: 일곱 가지 가운데 해당하는 것을 모두 담아 보냈습니다.

② 엉뚱한 길로 감후속 메시지를 보낸 뒤 작업이 고쳐 준 방향으로 갑니다.

⑤ 가져오기 실패다시 시도한 가져오기가 오류 없이 끝납니다.

막히면

증상할 일
어느 증상인지 모르겠음먼저 작업을 엽니다. 작업이 기다리는 중이면 지금 상태와 Aside 의 안내가 거기에 있습니다. 그 내용을 보고 증상 고르기로 돌아갑니다.
답했는데 이어 하기 동작이 보이지 않음원문은 “화면에 이어 하기 동작이 보이면 이어 간다”고만 적습니다. 보이지 않고 계속 멈춰 있다면 ⑥ 신고로 갑니다.
후속 메시지를 보냈는데 한참 뒤에야 반영됨후속 메시지 동작이 Queue 일 수 있습니다. Queue 는 지금 실행이 끝난 뒤에 반영합니다. 바로 고쳐야 한다면 Settings → Agents → Chat 에서 Steer 를 고릅니다.
여섯 가지를 확인했는데도 자동 입력이 안 뜸다른 비밀번호 관리 확장 프로그램을 쓰거나 금고가 열리지 않는 경우는 따로 다룹니다 — 완전 가이드 10장 문제 해결.
여기에 없는 증상금고 잠금 해제, 스트리밍 사이트 재생, 브라우저 동기화, Aside 가 계속 다시 시작되는 문제, 성능 문제 신고 등은 완전 가이드 10장 문제 해결에서 찾습니다.
