CHAPTER 01

설치와 첫 작업

Aside 를 내려받아 설치하고, 쓰던 브라우저의 자료를 옮겨 온 뒤, 에이전트에게 첫 일을 맡기는 데까지 갑니다. 이 장을 마치면 Aside 가 내 컴퓨터에서 돌아가고, 첫 작업 하나가 보내져 있습니다.

내려받기와 설치

Aside 는 macOS 와 Windows 에서 쓰는 AI 브라우저입니다. aside.com/download 를 열면 “You’re almost there!”(거의 다 왔어요)라는 화면과 함께 설치 파일(프로그램을 컴퓨터에 깔아 주는 파일) 내려받기가 시작됩니다. 알아 둘 것은 두 가지입니다.

  • 버전 고르기 — 내 컴퓨터에 맞는 버전이 자동으로 골라지지 않았다면 직접 고릅니다. Mac 용 화면에도 “Choose architecture”(프로세서 종류 고르기) 항목이 있습니다.
  • 내려받기가 시작되지 않을 때 — 화면 위쪽의 수동 내려받기 링크(manual download link)를 눌러 설치 파일을 Downloads(다운로드) 폴더에 저장합니다.
  1. Aside.dmg 열기Downloads(다운로드) 폴더에 내려받은 Aside.dmg 를 엽니다. dmg 는 디스크 이미지(disk image)(Mac 에서 프로그램을 담아 나눠 주는 꾸러미 파일)입니다.
  2. Applications 폴더로 끌어다 놓기열린 창에서 Aside 아이콘을 Applications(응용 프로그램) 폴더로 끌어다 놓습니다.
  3. Applications 폴더에서 Aside 열기이제부터는 Applications 폴더에 있는 Aside 를 실행합니다.
  1. 내려받은 실행 파일 열기내려받은 실행 파일(executable)(열면 바로 프로그램이 돌아가는 파일 — 여기서는 설치 프로그램)을 엽니다. x64 용과 ARM64 용 가운데 내 컴퓨터에 맞는 것을 받았는지 확인합니다.
  2. 설치 프로그램의 안내 따르기화면에 나오는 안내대로 진행합니다.
  3. Aside 열기설치가 끝나면 Aside 를 엽니다.

어느 쪽이든 설치가 끝나면 Aside 를 열고 설정 화면을 따라가면 됩니다. 그 차례가 바로 다음 소절입니다. 내려받기 화면에는 설치되는 동안 둘러볼 곳(커뮤니티·소식·문서)도 안내되어 있는데, 이 장 끝의 도움 받을 곳에 정리했습니다.

가입과 설정 5단계

Aside 를 처음 열면 다섯 단계를 차례로 거칩니다. 아래 상자의 다음 버튼을 눌러 한 단계씩 보세요.

1단계 — Aside 열기 (Open Aside). 설치한 Aside 를 엽니다. Mac 이라면 Applications 폴더에 있습니다.

2단계 — 로그인하거나 계정 만들기 (Sign in or create an account). Aside 계정이 있으면 로그인하고, 없으면 새로 만듭니다. Aside 를 쓰려면 계정이 꼭 있어야 합니다.

3단계 — 브라우저 데이터 가져오기 (Import browser data). 쓰던 브라우저의 방문 기록, 쿠키(사이트가 내 브라우저에 남겨 두는 작은 정보 조각), 북마크(즐겨찾기)를 Aside 로 옮겨 옵니다. 자세한 순서는 「브라우저 데이터 가져오기」 소절에 있습니다.

4단계 — 비밀번호 관리자 설정 (Set up Password Manager). 비밀번호 관리자(Password Manager)(로그인 정보를 보관하고 대신 입력해 주는 금고. Aside Vault 라고도 부릅니다)를 설정합니다. 에이전트가 내 비밀번호를 보지 않고도 로그인할 수 있게 해 주는 장치입니다. 자세한 내용은 5장에서 다룹니다.

5단계 — 작업 시작하기 (Start a task). 이제 에이전트(사람 대신 브라우저를 조작해 일하는 AI)에게 첫 일을 맡깁니다. 보내는 법은 「첫 작업 보내기 4단계」 소절에 있습니다.

한 줄로 외우기 열기 → 계정 → 가져오기 → 비밀번호 → 첫 작업. 화면이 이 순서로 안내하므로 외우지 않아도 따라갈 수 있습니다.

첫 작업 보내기 4단계

작업(task)(에이전트에게 맡기는 일 하나)을 보내는 순서는 네 단계입니다. 그 전에 한 가지만 해 두면 좋습니다 — 일에 쓸 사이트에 먼저 로그인해 두는 것입니다. 에이전트(사람 대신 브라우저를 조작해 일하는 AI)는 그 사이트를 직접 다루므로, 서비스마다 연동(AI 도구가 서비스를 쓰려고 미리 맺어 두는 연결)을 따로 설정할 필요가 없습니다. 내려받기 화면은 조사, 메시지, 스프레드시트(엑셀 같은 표 문서) 일을 도와 달라고 해 보라고 권합니다.

1단계 — 시작할 곳 고르기. 작업은 작업 페이지(task page)(작업을 새로 적어 보내는 화면)나 사이드 패널(side panel)(보고 있는 페이지 옆에 여는 창)에서 시작합니다. 어느 쪽이 맞는지는 바로 다음 소절에서 정리합니다. 원문은 이 대목에서 작업 페이지를 여는 방법까지는 적지 않았습니다 — 새 탭 입력창의 Ask AI 모드와 New Task(새 작업) 단축키, 사이드 패널 쓰는 법은 2장에 있습니다.

2단계 — 원하는 결과 적기 (Describe the outcome). 요청문(에이전트에게 써 보내는 글)에 “어떻게 눌러라”가 아니라 “무엇이 되어 있기를 바라는지”를 적습니다. 이때 웹사이트, 계정, 파일, 원하는 결과의 이름을 분명히 댑니다.

요청문 예시 — 공식 문서의 예시를 한국어로 옮긴 것 (화면 모양은 흉내)
Rippling 에 로그인해서 이번 달 내 급여명세서를 받아 PDF 를 Downloads(다운로드 폴더)에 저장해 줘. Rippling 이 MFA 나 인증 코드를 요구하면 나에게 물어봐.▍
테두리 색: 청록 = 웹사이트 · 초록 = 원하는 결과 · 주황 = 파일과 둘 곳. 이 예시는 계정 이름을 따로 적지 않고 “Rippling 에 로그인해서”라고만 했습니다.
원문(영어)

Sign in to Rippling, get my paystubs for this month, and save the PDFs to Downloads. Ask if Rippling needs MFA or a verification code.

공식 문서 「Run tasks」(작업 실행)가 좋은 요청의 예로 든 문장입니다. Rippling 은 원문 예시 속 서비스 이름이고(원문에 따로 풀이는 없습니다. 예시에서는 급여명세서를 받는 곳으로 나옵니다), MFA 는 여러 단계 인증(비밀번호 말고도 한 번 더 본인임을 확인하는 절차)입니다. 요청문을 잘 쓰는 법은 3장 「좋은 요청 쓰는 법」에서 이어집니다.

3단계 — 필요하면 권한 고르기 (Choose permissions if needed). 작업에 내 컴퓨터의 파일이 필요하다면 권한 모드(permission mode)(에이전트가 내 컴퓨터의 파일을 어디까지 다룰 수 있는지 정하는 단계)와 작업 폴더(working folder)(에이전트가 파일을 읽고 쓸 폴더)를 고릅니다. 파일이 필요 없는 작업이면 이 단계는 건너뜁니다. 권한 모드의 종류와 고르는 법은 3장에서 다룹니다.

4단계 — 보내기 (Send the task). 작업을 보냅니다. 이제 에이전트가 일을 시작합니다. 작업이 진행되는 모습과 중간에 말을 거는 법은 3장에 있습니다.

한눈에 정리
  • 준비물은 Aside 계정과 설치된 Aside 브라우저 두 가지입니다. macOS 15.0 이상, Windows 10 버전 22H2 이상 또는 Windows 11 에서 돌아갑니다(2026-11-09 수집 기준).
  • aside.com/download 에서 내려받습니다. Mac 은 Aside.dmg 를 열어 Aside 를 Applications 폴더로 끌어다 놓고, Windows 는 내려받은 실행 파일을 열어 안내를 따릅니다.
  • 처음 켜면 열기 → 로그인·가입 → 브라우저 데이터 가져오기 → 비밀번호 관리자 설정 → 작업 시작 다섯 단계를 거칩니다.
  • 가져오는 것은 방문 기록·쿠키·북마크 세 가지입니다. Safari 는 File → Export 로 만든 ZIP 파일을 올려야 하고, ZIP 이 아니면 거부됩니다.
  • 첫 작업은 시작할 곳 고르기 → 원하는 결과 적기 → (파일이 필요하면) 권한 고르기 → 보내기입니다. 요청문에는 웹사이트·계정·파일·원하는 결과의 이름을 댑니다.
  • 여러 사이트·계정·파일에 걸친 일은 작업 페이지, 지금 보는 페이지가 재료인 일은 사이드 패널에서 시작합니다.

CHAPTER 02

브라우저로 쓰기

Aside 는 매일 쓰는 브라우저이면서, 그 자리에서 AI 에게 일을 맡길 수 있는 브라우저입니다. 새 탭에서 바로 맡기고, 두 페이지를 나란히 놓고, 화면의 글자·그림을 골라 묻고, 보고 있는 페이지 옆에 창을 열어 그 페이지를 통째로 맡기는 방법을 차례로 익힙니다.

Ask AI — 새 탭에서 바로 맡기기

쉽게 말하면 새 탭의 입력창에는 스위치가 하나 달려 있습니다. Search 쪽에 두면 평소처럼 검색하는 칸이고, Ask AI 쪽으로 넘기면 “이 일 좀 해 줘”라고 적어 보내는 칸이 됩니다.

Ask AI(AI 에게 맡기기)는 브라우저 화면에서 곧바로 작업(task — 에이전트에게 맡기는 일 하나)을 시작하고 싶을 때 씁니다. 에이전트(agent — 사람 대신 브라우저를 조작해 일하는 AI)가 그 글을 받아 일을 시작합니다. 새 탭의 입력창(omnibox)(주소와 검색어를 함께 받는 입력 칸)에는 Search(검색)와 Ask AI 두 가지 모드가 있습니다.

잘 통하는 요청문과 예시 3개

Ask AI 는 요청문(prompt — 에이전트에게 써 보내는 글)에 어느 사이트에서, 어떤 결과를 원하는지, 에이전트가 지켜야 할 한계가 무엇인지를 적어 줄 때 가장 잘 움직입니다. 사람에게 심부름을 시킬 때 “어디 가서, 무엇을 가져오고, 이것만은 하지 마”라고 말해 주는 것과 같습니다.

원문이 드는 예시는 세 가지입니다. 한국어로 옮긴 글 아래에 원문 영어를 함께 둡니다.

  • 새 탭 입력창에는 Search(검색)와 Ask AI(AI 에게 맡기기) 두 모드가 있고, 작업 입력창에서 @ 로 맥락을 붙입니다. Cmd/Ctrl+E 는 Ask Aside 를 시작합니다.
  • 요청문에는 사이트, 원하는 결과, 지켜야 할 한계를 적습니다. 본인 확인 단계는 “물어봐”, 되돌리기 어려운 행동은 “하기 전에 멈춰”.

  • 선택 단축은 처음부터 켜져 있습니다. 글자 선택은 Summarize·Translate, 올가미 선택은 Copy code·Search image 가 기본이고, Settings → Lasso 에서 끄기·순서 바꾸기·고치기·지우기·새로 만들기를 합니다.
  • 단축은 요청문 실행, 고른 내용 복사, 주소 열기를 할 수 있고, 틀에 {text}(올가미는 지원되는 경우 {code}·{image} 도)를 넣습니다.

  • 사이드 패널 초안은 페이지 맥락별로 보관되어, 떠났다 돌아와도 시작한 탭에 남아 있을 수 있습니다.

CHAPTER 03

작업 맡기기

한 번 묻고 답을 받는 것으로 끝나지 않는 일은 “작업”으로 맡깁니다. 작업을 시작할 때 무엇을 정하는지, 작업이 도중에 멈추면 왜 멈추는지, 기록과 파일은 어디에 남는지, 그리고 어떻게 써야 원하는 결과가 나오는지를 다룹니다.

파일 다루기

방문 기록 검색

승인 요청

자동 입력으로 로그인

허용해 둔 자동 입력으로 사이트에 로그인합니다. (5장)

작업은 한 번에 끝까지 달리지 않을 수 있습니다. 여러 단계를 이어서 진행하다가, 내 입력을 기다리며 멈추거나, 승인을 요청하거나, 기다린 뒤에 다시 이어 갑니다.

작업이 기다리고 있다면 열어 보세요 Aside 는 알림을 기다렸다가 작업을 이어 갈 수도 있습니다. 작업이 기다리는 중일 때는 그 작업을 열어 지금 상태와 Aside 가 남긴 안내를 확인합니다.

좋은 요청 쓰는 법

원칙은 한 줄입니다. Aside 에게 원하는 결과와, 그 일에 써야 할 사이트나 파일을 알려 줍니다. 같은 일을 두 가지로 써 보면 차이가 보입니다.

한눈에 정리
  • 작업은 브라우저 조작·검색·파일·자동 입력·승인이 여러 번 필요한 일에 씁니다.
  • 새 작업에서 정하는 것: 모드(Default·Incognito), 권한(Read only·Guard·Full access), 작업 폴더, 모델. 권한 규칙은 6장.
  • 작업은 사이트 이동, 웹 검색, 파일, 방문 기록 검색, 승인 요청, 허용된 자동 입력 로그인을 할 수 있고, 도중에 입력을 기다리며 멈추거나 승인을 요청하거나 기다린 뒤 재개합니다. 기다리는 작업은 열어서 상태와 안내를 확인합니다.
  • 작업 상세 페이지에서 만들거나 바꾼 파일을 보고, 이미지·PDF·HTML·텍스트 파일·파일 메타데이터를 미리 봅니다.
  • 채팅을 Delete 하면 되돌릴 수 없고 그 채팅이 만든 루틴도 지워지지만, 대화 기록·첨부·만들어진 파일은 컴퓨터 폴더에 남습니다. Archive 는 채팅과 루틴을 남기되 복원(Unarchive)할 때까지 루틴을 멈춥니다.
  • 좋은 요청은 원하는 결과와 쓸 사이트·파일을 적습니다. 계정, 다룰 자료, 둘 곳, 하지 말 행동을 이름으로 적고, 돈·고객 정보·로그인 정보·파일을 건드리면 한계를 답니다.
  • 후속 메시지: Queue 는 지금 실행이 끝난 뒤 반영, Steer 는 도중에 바로 반영. Settings → Agents → Chat 에서 고릅니다.

CHAPTER 04

반복 작업과 기억

매주 같은 요약을 뽑거나 며칠 뒤 같은 대화를 이어 가야 하는 일은 매번 손으로 시작하기 번거롭습니다. Aside 의 루틴은 이런 반복 일을 예약해 두는 기능이고, 기억은 지난 방문 기록·채팅·작업에서 얻은 사정을 다음 일에 다시 꺼내 쓰게 해 주는 기능입니다.

루틴이란

쉽게 말하면 루틴은 “할 일이 묶여 있는 알람 시계”입니다. 알람을 한 번 맞춰 두면 그때마다 알아서 울리듯, 할 일을 한 번 정해 두면 Aside 가 때가 될 때마다 그 일을 시작합니다.

루틴(routine)은 되풀이되는 일을 내가 매번 직접 시작하지 않아도 Aside 가 돌려 주는 기능입니다. 여기서 “일”은 작업(task), 곧 에이전트(agent)(사람 대신 브라우저를 조작해 일하는 AI)에게 맡기는 일 하나를 말합니다. 평소에는 내가 요청을 써 보내야 작업이 시작되지만, 루틴으로 걸어 두면 그 첫걸음을 Aside 가 뗍니다.

루틴은 Settings → Routines(설정 → 루틴)에서 만들고 관리합니다. 자세한 것은 아래 「루틴 관리」에서 다룹니다. 작업을 맡기는 기본 방법은 3장을 보세요.

두 종류: Cron 루틴과 Heartbeat 루틴

루틴(routine)(반복되는 일을 예약해 두면 Aside 가 알아서 돌려 주는 기능)에는 두 종류가 있습니다. 차이는 한 가지입니다. 때가 됐을 때 새 작업을 시작하느냐, 있던 채팅을 이어 가느냐입니다. 채팅(chat)은 작업 하나의 대화 기록을 말합니다.

종류하는 일어울리는 일
Cron routine
(Cron 루틴)		정해 둔 일정에 맞춰 새 작업을 시작합니다.그 자체로 끝나는 독립된 반복 일. 원문의 예: 주간 요약(weekly summary).
Heartbeat routine
(Heartbeat 루틴)		있던 채팅을 깨워 그 채팅을 이어 갑니다.같은 채팅이 나중에 새 맥락(context)(앞뒤 사정 — 그동안 달라진 상황이나 새로 생긴 정보)을 가지고 계속되어야 하는 일.
고르는 기준 “지난번 대화를 몰라도 되는 일인가?”를 물어보세요. 몰라도 되면 Cron 루틴, 지난 대화에 이어 붙여야 하면 Heartbeat 루틴입니다. Cron 은 컴퓨터에서 ‘정해진 일정에 맞춰 일을 돌리는 예약’을 가리키는 말이고, Heartbeat 는 ‘심장 박동’이라는 뜻의 영어입니다. 두 이름의 유래는 원문에 설명이 없습니다.

기억이란

쉽게 말하면 단골 가게 주인은 “늘 드시던 걸로 드릴까요?”라고 묻습니다. 지난번 일을 기억하니 처음부터 다시 설명하지 않아도 됩니다. Aside 의 기억도 같은 역할을 합니다.

기억(Memory)은 Aside 가 방문 기록(browsing history)·채팅·작업에서 얻은 맥락(context)(앞뒤 사정 — 누구와 어떤 일을 어디서 했는지 같은 배경 정보)을 다시 쓰도록 돕는 기능입니다. 여기서 채팅(chat)은 작업 하나의 대화 기록, 작업(task)은 에이전트(agent)(사람 대신 브라우저를 조작해 일하는 AI)에게 맡기는 일 하나를 뜻합니다.

Aside 사이트는 이를 “방문 기록이 기억이 된다”고 표현합니다. 어떤 일에 어떤 사이트를 쓰는지 Aside 가 알게 되므로 매번 사정을 다시 설명하지 않아도 된다는 것입니다. 사이트가 드는 요청문(prompt)(에이전트에게 써 보내는 글) 예시는 다음과 같습니다.

요청문 예시 “어제 내가 열어 본 지원자를 찾아서 면접 메모를 준비해 줘.” 원문: Find the candidate I opened yesterday and prep interview notes

‘어제 열어 본 지원자’가 누구인지 적지 않았는데도 요청이 성립하는 까닭은, 방문 기록이 그 빈칸을 채워 주기 때문입니다.

기억 설정에서 정하는 것은 두 가지입니다. 기억을 만들지 말지(아래 「기억 켜고 끄기」), 그리고 얼마나 오래 둘지(「보관 기간」)입니다.

기억 켜고 끄기

기억(Memory)(Aside 가 지난 방문 기록·채팅·작업의 사정을 다시 쓰게 해 주는 기능)을 쓸지 말지는 내가 정합니다. Settings → Memory → Configure(설정 → 기억 → 구성)를 열어 켜거나 끕니다.

  • 켜 두면 Aside 는 방문 기록을 맥락으로 쓸 수 있고, 채팅과 작업 활동에서 기억을 만들 수 있습니다.
  • 끄는 때는 새 채팅이나 작업이 기억을 만들지 않기를 바랄 때입니다.
끄면 지난 기억이 어떻게 되는지는 문서에 없습니다 문서는 끄기를 “새 채팅·작업이 기억을 만들지 않게 하는 것”으로만 설명하고, 이미 저장된 기억이 지워지는지는 적지 않았습니다. 이미 저장된 기억을 보고 고치는 방법은 아래 「살펴보고 고치기」에 있고, 개인정보 설정은 6장에서 다룹니다.
한눈에 정리
  • 루틴은 반복되는 일을 손으로 매번 시작하지 않아도 Aside 가 돌려 주는 기능이며, Settings → Routines 에서 관리합니다.
  • Cron 루틴은 정한 일정마다 새 작업을 시작하고(예: 주간 요약), Heartbeat 루틴은 있던 채팅을 깨워 새 맥락으로 이어 갑니다.

CHAPTER 05

비밀번호와 로그인

에이전트에게 일을 맡기다 보면 금세 로그인 화면에 막힙니다. 그렇다고 AI 에게 비밀번호를 알려 주기는 꺼림칙합니다. Aside 의 비밀번호 금고 Aside Vault 는 이 문제를 “비밀번호는 금고가 직접 채워 넣고, AI 는 그 글자를 보지 못하게” 하는 방식으로 풉니다.

Aside Vault 가 하는 일

쉽게 말하면 Aside Vault 는 “열쇠를 대신 꽂아 주는 관리인”입니다. 에이전트는 관리인에게 “이 문 좀 열어 주세요”라고 부탁할 수는 있지만 열쇠를 손에 쥐지는 못합니다. 관리인이 문에 직접 열쇠를 꽂아 주고, 열쇠는 다시 금고로 돌아갑니다.

Aside Vault(Aside 의 비밀번호 금고. 도움말에서는 Password Manager — 비밀번호 관리자 — 라고도 부르며 같은 기능입니다)는 로그인 정보를 대신 보관하고, 자동 입력(autofill)(아이디·비밀번호 칸을 대신 채워 주는 것)으로 Aside 가 로그인하게 해 줍니다. 에이전트(agent)(사람 대신 브라우저를 조작해 일하는 AI)는 ‘로그인하기’라는 동작은 쓸 수 있지만 비밀번호 원문은 받지 않습니다.

급여 도구, 대시보드(현황을 한 화면에 모아 보여 주는 관리 화면), 이메일, CRM(고객 관리 도구), 청구·결제 페이지, 사내 도구처럼 로그인 화면 뒤에 있는 곳에서 일을 시키고 싶을 때 씁니다. 하는 일은 다섯 가지입니다.

1. 로그인 정보 저장

웹사이트 로그인 정보를 Aside 안에 저장합니다.

2. 맞는 로그인 제안

로그인 페이지에서 그 사이트와 일치하는 로그인 정보를 제안합니다.

3. 보여 주지 않고 입력

비밀번호를 에이전트에게 보여 주지 않은 채 웹사이트에 채워 넣습니다.

4. 비밀번호 밖의 인증 지원

사이트가 요구하는 곳에서 패스키(passkey)(비밀번호 대신 기기의 잠금 해제로 로그인하는 방식), FIDO2(패스키·보안 키 로그인에 쓰이는 표준 규격), TOTP(시간에 따라 바뀌는 일회용 인증 번호) 확인 창을 지원합니다.

5. 에이전트 사용 통제

에이전트가 저장된 로그인 정보를 언제 쓸 수 있는지 내가 정합니다.

Aside 사이트는 Aside Vault 를 “에이전트를 위해 만든 첫 비밀번호 관리자(The first password manager built for agents)”라고 소개합니다. 이 문구는 Aside 가 내세우는 표현입니다.

에이전트가 로그인하는 순서

에이전트(agent)(사람 대신 브라우저를 조작해 일하는 AI)가 작업을 하다가 로그인 페이지를 만나면, 비밀번호를 다루는 일은 에이전트가 아니라 Aside Vault(Aside 의 비밀번호 금고)가 맡습니다. 순서는 아래 그림과 같습니다.

  1. 작업이 로그인 페이지에 닿습니다.에이전트가 일을 하다가 로그인이 필요한 화면을 만납니다.
  2. Aside 가 두 가지를 확인합니다.지금 페이지의 주소인 대상 URL(웹 주소)과, 내가 정해 둔 비밀번호 접근 설정입니다.
  3. 허용된 로그인 정보가 있으면 자동 입력합니다.그 주소와 일치하고 사용이 허용된 로그인 정보가 있을 때, Aside 가 페이지에 채워 넣을 수 있습니다.
AI 는 비밀번호 원문을 받지 않습니다 Aside 는 로그인 정보를 웹사이트에 채워 넣을 뿐이고, 저장된 비밀번호는 내 기기 안에 머물며 AI 에게는 숨겨집니다. 일치하는 로그인이 있는지 찾을 때에도 허용된 금고 항목만 살피고, 그 과정에서 저장된 비밀번호를 에이전트에게 드러내지 않습니다.

  • 자동 입력은 기본으로 켜져 있고 일치하는 로그인만 채웁니다. google.com · youtube.com · gmail.com 같은 계정 도메인은 기본적으로 같은 것으로 봅니다.
  • 비밀번호는 Settings → Passwords → Import 에서 아홉 가지 출처로부터 가져옵니다. 끝나면 내보낸 파일은 백업이 필요할 때만 남깁니다.
  • AI 접근 정책은 Always allow(기본값) · While unlocked · Never 셋입니다. 가져온 항목은 항목별로 덮어쓸 수 있고, 시크릿 세션에서는 에이전트가 금고를 쓸 수 없습니다.
  • Clear vault data 는 항목·금고 열쇠·금고를 지우고 새 Personal 금고를 만든 뒤 그 상태를 동기화합니다. 지우기 전에 내보내기부터 합니다.
  • 다른 제품과의 비교표는 Aside 가 자기 사이트에 실은 것입니다.

비밀번호의 경계

Aside 는 자체 비밀번호 관리자(Password Manager — 비밀번호 금고 Aside Vault 와 같은 기능)의 자동 입력(autofill)(저장해 둔 아이디·비밀번호를 로그인 칸에 대신 채워 주는 기능)으로 사이트에 로그인할 수 있습니다. 이때 지켜지는 선이 하나 있습니다. 저장된 비밀번호의 값은 AI 에이전트(사람 대신 브라우저를 조작해 일하는 AI)에게 보이지 않습니다.

쉽게 말하면 호텔 직원에게 “제 방 문 좀 열어 주세요”라고 부탁하면 직원은 마스터키로 문을 열어 주지만, 그 열쇠를 손님에게 건네지는 않습니다. 에이전트는 “로그인해 줘”라고 부탁하는 쪽이고, 비밀번호를 칸에 채우는 일은 금고 쪽이 합니다.

Aside 는 자동 입력할 내용을 만들기 전에 두 가지를 확인합니다. 비밀번호 접근 정책(password access policy)(그 비밀번호를 써도 되는지 정해 둔 규칙 — 원문에 더 자세한 설명은 없음)과, 비밀번호를 넣으려는 대상 주소(URL)(웹페이지의 주소)입니다. 앞에서 본 것처럼 권한 모드를 Full access 로 올려도 이 경계는 그대로입니다. 금고와 자동 입력을 쓰는 방법은 5장 「비밀번호와 로그인」에서 다룹니다.

CHAPTER 07

AI 모델과 요금

Aside 의 에이전트는 AI 모델이 있어야 움직입니다. 그 모델을 어디에서 끌어다 쓸 수 있는지(제공처 네 가지), 그리고 Aside 요금제와 크레딧이 어떻게 돌아가는지를 다룹니다.

모델 제공처 네 가지

쉽게 말하면 에이전트(agent)(사람 대신 브라우저를 조작해 일하는 AI)가 일꾼이라면 모델(model)(요청을 이해하고 답과 행동을 만들어 내는 AI 의 두뇌 프로그램)은 그 일꾼의 두뇌입니다. Aside 는 이 두뇌를 네 군데에서 빌려 올 수 있습니다. Aside 가 직접 주는 것, 내가 이미 구독 중인 것, 내가 따로 계약한 것, 내 컴퓨터 안에 있는 것입니다.

Settings → Models(설정 → 모델)에서 Aside 가 쓸 모델 제공처(provider)(모델을 대 주는 곳)를 고릅니다. Aside 가 지원하는 제공처는 네 종류입니다.

직무별 활용 사례

Aside 블로그에 실린 직무별 글 다섯 편(운영 · 채용·인사 · 영업 · 리서치 · 개발)의 사례를 한자리에 모았습니다. 다섯 글의 모양은 같습니다. Aside 가 여러 사이트를 돌며 자료를 모아 「검토할 묶음」을 만들고, 보내기·승인·저장 같은 결정은 사람이 합니다.

다섯 직무에 공통인 틀 — 준비는 Aside, 승인은 사람

쉽게 말하면 회의 전에 자료를 챙겨 오는 비서를 떠올리면 됩니다. 비서는 여러 부서를 돌며 서류를 모으고, 이상한 곳에 표시를 하고, 보낼 편지의 초안까지 써 둡니다. 하지만 도장은 찍지 않습니다. 도장은 내가 찍습니다.

다섯 글이 다루는 일은 생김새가 같습니다. 매주 같은 보고서가 돌아오는데, 근거는 대시보드(숫자와 그래프를 한 화면에 모아 보여 주는 페이지), 업체 포털(로그인해서 들어가는 업체 전용 사이트), 스프레드시트, 메일에 흩어져 있습니다. 이 일을 Aside 의 에이전트(사람 대신 브라우저를 조작해 일하는 AI)에게 맡기면, 내가 다른 일을 하는 동안 그 페이지들을 직접 열어 읽고, 파일을 내려받고, 화면 사진(스크린숏)을 찍어 검토할 묶음으로 돌려줍니다. 묶음에는 출처 링크와, 사람이 봐야 할 예외 목록이 함께 들어 있습니다.

글마다 "어디서 멈추는가"를 따로 적어 두었습니다. 표현은 달라도 뜻은 하나입니다 — 되돌리기 어려운 일 앞에서는 사람이 누릅니다.

CHAPTER 09

개발자 도구 (CLI · MCP · REPL)

Aside 는 브라우저 화면에서 직접 쓰는 것 말고도, 터미널(글자로 명령을 쳐서 컴퓨터를 부리는 창)·다른 AI 도구·스크립트(할 일을 미리 적어 둔 명령 묶음)에서 불러 쓸 수 있는 통로 세 가지를 갖추고 있습니다. 개발자를 위한 장이지만, 개발을 하지 않는 분도 “이런 통로가 있고 언제 쓰는지”만 알아 두면 충분합니다.

세 가지 통로: CLI · MCP · REPL

쉽게 말하면 Aside 브라우저를 “일을 대신 해 주는 직원이 있는 사무실”이라고 해 봅시다. 지금까지는 사무실에 직접 들어가서(브라우저 화면에서) 일을 맡겼습니다. 개발자 도구는 이 사무실에 따로 난 창구 세 개입니다. 말로 부탁을 적어 넣는 창구(CLI), 다른 회사 직원이 정해진 양식으로 일을 넘기는 창구(MCP), 기계 손잡이를 직접 잡고 한 동작씩 움직이는 창구(REPL)입니다.

Aside 에는 CLI(Command-Line Interface)(명령줄 인터페이스 — 터미널, 곧 글자로 명령을 쳐서 컴퓨터를 부리는 창에 명령을 쳐서 프로그램을 쓰는 방식), MCP(Model Context Protocol)(AI 도구가 바깥 프로그램의 기능을 불러 쓸 때 따르는 공통 연결 규칙) 지원, 그리고 브라우저 자동화용 REPL(코드 한 줄을 넣으면 바로 실행하고 결과를 돌려주는 대화식 실행 창)이 들어 있습니다. 셋 모두 사용자의 브라우저와 계정을 가지고 일하게 해 주는 통로입니다.

CLI — 말로 맡기기

사람이 쓰는 말로 적은 요청을 터미널에서 바로 맡길 때 씁니다.

MCP — 쓰던 에이전트 연결

이미 쓰고 있는 에이전트(사람 대신 일하는 AI)나 코딩 도구에 Aside 를 붙일 때 씁니다.

REPL — 직접 자동 조작

브라우저를 코드로 한 단계씩 직접 움직일 때 씁니다.

Aside 브라우저가 돌아가는 환경 개발자 도구는 Aside 브라우저와 함께 씁니다. Aside 브라우저는 macOS 15.0 이상, 그리고 Windows 10 버전 22H2 이상 또는 Windows 11 에서 동작하며, Windows 용 설치 파일은 x64 와 ARM64(컴퓨터 프로세서 종류에 따른 구분) 두 가지가 있습니다(2026-11-09 수집 기준). 브라우저 설치는 1장 설치와 첫 작업을 보세요.

언제 Aside 를 쓰나

Aside 개발자 문서는 이 도구들이 잘 맞는 일로 다음 네 가지를 듭니다.

만들고 있는 웹 앱 점검

내 컴퓨터에서 띄운 웹 앱을 진짜 브라우저에서 스모크 테스트(smoke test)(핵심 기능이 일단 돌아가는지만 빠르게 훑는 점검)합니다.

여러 사이트 조사

여러 웹사이트에서 정보를 찾아 사용자에게 요약해 줍니다.

로그인된 업무 도구에서 일하기

사용자의 허락을 받아, 로그인해 둔 이메일·대시보드(현황판 화면)·사내 도구를 오가며 일합니다.

페이지 들여다보기

REPL 로 페이지를 살펴보고, 스크린숏을 찍고, 정해진 순서대로 브라우저를 조작합니다.

브라우저 작업 실행하고 이어 하기

aside 뒤에 할 일을 문장으로 적으면, 터미널(글자로 명령을 쳐서 컴퓨터를 부리는 창)에서 브라우저 에이전트 세션(session)(CLI 로 시작한 작업 한 건)이 시작됩니다.

터미널
aside "Open localhost:3000 and run a smoke test"

뜻: “localhost:3000(내 컴퓨터에서 띄워 둔 웹 앱의 주소)을 열고 스모크 테스트(핵심 기능이 일단 돌아가는지만 빠르게 훑는 점검)를 해 줘.”

이미 있는 세션을 이어 가려면 session resume 을 씁니다. <session-id> 자리에는 이어 갈 세션의 ID 를 넣고, 뒤에 이어서 할 말(예시는 “Continue” — 계속해 줘)을 적습니다.

aside session resume <session-id> "Continue"
CLI 세션은 금방 사라집니다 CLI 세션은 끝난 뒤 약 15분이 지나면 지워지고, 브라우저의 채팅 목록에도 나타나지 않습니다. 남겨 두려면 다음 명령을 실행합니다. 
aside settings save-sessions true

브라우저 화면에서 작업을 맡기는 방법은 3장 작업 맡기기에 있습니다.

한눈에 정리
  • Aside 에는 화면 밖에서 불러 쓰는 통로가 셋 있습니다 — 말로 맡기는 CLI, 쓰던 에이전트를 잇는 MCP, 코드로 직접 조작하는 REPL. 셋 다 사용자의 브라우저와 계정으로 일합니다.
  • 잘 맞는 일: 만들고 있는 웹 앱의 스모크 테스트, 여러 사이트 조사와 요약, 허락을 받고 로그인된 업무 도구에서 일하기, 페이지 살펴보기·스크린숏·정해진 순서의 조작.
  • 계정 접근이나 민감한 동작 전에는 허락을 받고, 로그인 화면·승인 요청을 건너뛰지 않습니다.
  • CLI 는 개발자 설정 화면에서 설치하거나, macOS 는 터미널 한 줄, Windows 는 서명을 확인하는 PowerShell 스크립트로 설치합니다. 업데이트 확인은 aside --update.
  • 다른 컴퓨터에서 로그인할 때는 aside login 전에 ASIDE_CLI_AUTH_PATH 를 정하고, Signed in as ... 가 나올 때까지 기다리며, 이후 모든 명령에 같은 값을 넘깁니다.
  • aside "…" 로 시작하고 aside session resume 으로 이어 갑니다. CLI 세션은 끝난 뒤 약 15분이면 지워지고 채팅 목록에 나타나지 않으며, aside settings save-sessions true 로 보관합니다.
  • 계정이 여럿이면 aside account list · status · use 와 --account 로 고릅니다.
  • aside mcp 와 mcp.json 설정으로 다른 도구에 연결하고, aside repl 로 브라우저를 직접 조작합니다.
  • 공개 다운로드 API 는 설치 파일 주소만 알려 주며, 브라우저 작업에는 쓰지 않습니다.

Aside 는 하네스(AI 모델을 감싸 도구와 지시를 건네는 바깥 프로그램)의 대부분을 처음부터 직접 만들었다고 밝혔습니다. 바탕으로는 pi-mono/core 라는 프로그램을 골랐지만, 그 위에 올라가는 나머지 — 예를 들면 길어진 대화를 줄여 정리하기(compaction), 스킬(에이전트가 따를 절차를 적어 둔 것), 훅(hook)(정해 둔 순간에 끼어들어 실행되는 장치), 샌드박스(에이전트가 허락된 범위 밖을 건드리지 못하게 막는 울타리), 코드 실행 창(REPL), 글자 명령 창(bash), 브라우저 자동화 — 는 모두 직접 지었다고 합니다. 지키고 싶은 원칙이 있었기 때문이라고 합니다. 그 원칙이 아래 네 가지입니다.

① 모델이 배운 것을 따른다
AI 모델이 가장 많이 보고 배운 자료는 코드입니다. 그래서 Aside 의 핵심 도구는 코드를 받아 바로 실행하는 창이고, 그 문법은 가장 널리 쓰이는 브라우저 자동화 도구 Playwright 의 것을 따릅니다. 새 직원에게 낯선 사내 도구 대신 이미 손에 익은 도구를 쥐여 주는 것과 같습니다.
② 지시는 적을수록 똑똑해진다
AI 가 없는 사실을 지어내거나 엉뚱하게 구는 까닭은 주로 두 가지 — 지금 상태를 제대로 알려 주지 않았거나, 지시끼리 서로 부딪쳐서라고 봅니다. 그래서 기본 지시문을 짧게 유지합니다. 또 지시문을 AI 에게 쓰게 하지 않습니다.
③ 모델의 책상을 깨끗이 지킨다
모델이 한 번에 펼쳐 놓고 볼 수 있는 글의 양(컨텍스트 창)은 한정돼 있습니다. 거기에 쓸모없는 글이 쌓이면 모델의 실력이 빠르게 떨어집니다. 그래서 도구가 돌려주는 결과를 “알맹이는 많고 군더더기는 적게” 만듭니다.
④ 거인의 어깨 위에 선다
모든 것을 새로 발명하지 않았습니다. Codex · Claude Code · OpenCode · oh-my-opencode 같은 훌륭한 공개 프로젝트에서 빌려 왔다고 밝힙니다.
