PASEO 한눈에 보기 · 0.15.3 · 2026-11-09 기준

Paseo — AI 코딩 에이전트 여러 개를
내 컴퓨터에서 동시에 돌리고 어디서든 이어서 지휘

Paseo(파세오)는 에이전트 개발 환경(AI 에이전트에게 일을 시키며 개발하는 작업장 프로그램)입니다. 에이전트 실행, 파일 편집, 바뀐 곳 검토, 직접 돌려 보기를 한 앱에서 하고, 데스크톱·휴대폰·웹·명령 창 어디서든 같은 작업에 접속합니다. 무료·오픈소스(Apache-2.0)이고 사용 기록 수집이나 필수 계정이 없습니다.

1. 세 가지만 먼저

에이전트는 내가 데려온다

Paseo는 다른 에이전트를 관리할 뿐 직접 들고 있지 않습니다. Claude Code, Codex 같은 에이전트 프로그램을 하나 이상 직접 설치하고 로그인해 두어야 쓸 수 있습니다. 구독·설정·스킬은 쓰던 그대로입니다.

일은 내 컴퓨터에서

에이전트는 내 컴퓨터(또는 내 서버)에서 돕니다. Paseo는 코드를 어디로도 보내지 않고, 에이전트만 평소처럼 자기 서비스와 통신합니다.

채팅이 아니라 워크스페이스

일 하나마다 워크스페이스(일하는 자리)를 만들고, 그 안에 대화·터미널(글자로 명령을 입력하는 창)·브라우저·diff(바뀌기 전과 후의 차이)를 탭으로 함께 엽니다.

자세히: 완전 가이드 소개 · 그림으로 먼저: 쉬운 설명

2. 구조 — 데몬 하나에 창 여러 개

데몬(계속 켜져 에이전트와 워크스페이스를 맡아 돌리는 Paseo의 본체 프로그램)이 내 컴퓨터에서 일을 맡고, 앱들은 거기에 연결해 보고 지시합니다. 데스크톱 앱은 데몬을 품고 있어서 열면 함께 켜집니다. 화면 없는 서버에서는 명령 두 줄로 데몬만 켜거나 Docker(프로그램을 격리된 상자에 담아 돌리는 도구)용 공식 이미지를 씁니다(1장).

자세히: 1장 설치와 첫 실행

3. 작업 모델 — 프로젝트 › 워크스페이스 › 세션

단위무엇인가
프로젝트사이드바의 맨 위 단위. git 저장소, GitHub 프로젝트, 또는 데몬이 도는 컴퓨터의 아무 폴더.
워크스페이스일 하나를 하는 자리. 작업 폴더가 하나 딸려 있고, 에이전트 없이 먼저 만들어 둘 수도 있습니다.
세션워크스페이스 안에서 도는 것 — 에이전트 대화, 터미널, 브라우저, diff. 앱에서는 탭 하나. 같은 워크스페이스의 에이전트들은 작업 폴더를 함께 씁니다.

워크스페이스를 만들 때 격리(Isolation) 방식을 고릅니다.

Local

이미 있는 폴더(예: 원래 쓰던 작업 폴더)를 그대로 씁니다. 세션들이 지금 디스크에 있는 파일을 함께 쓸 때.

Worktree (New worktree)

워크트리(같은 프로젝트를 다른 폴더에 하나 더 꺼내 놓은 것)를 새로 만듭니다. 일마다 폴더와 브랜치(원본을 건드리지 않고 따로 작업하는 갈래)가 따로라 여러 에이전트가 동시에 고쳐도 섞이지 않습니다. 그 워크트리를 쓰는 워크스페이스를 모두 보관(archive — 다 쓴 것으로 치워 두기)하면 Paseo가 워크트리 폴더를 지웁니다.

자세히: 2장 프로젝트 · 워크스페이스 · 워크트리

4. 에이전트 — 프로바이더 두 갈래와 프로필

프로바이더는 Paseo에 연결해 쓰는 에이전트 프로그램 한 종류를 가리키는 말이고, 정확히는 Paseo와 그 프로그램 사이의 약속입니다(어떻게 실행하고, 출력을 받고, 입력을 돌려보내고, 어떤 모드가 있는지). 실제 프로그램은 내 컴퓨터에서 평범한 프로그램으로 돕니다. 어느 쪽이든 에이전트 프로그램은 내가 설치합니다.

갈래무엇인가예
Native supportPaseo에 전용 연결 장치가 들어 있어, 프로그램을 설치·로그인하면 자동으로 잡힙니다.Claude Code · Codex · OpenCode · Pi · Antigravity · Muse Code
ACP catalogAgent Client Protocol(에이전트와 앱이 대화하는 공통 규격)을 쓰는 에이전트는 범용 연결 장치로 지원합니다. 한 번 눌러 설치하는 목록이 있고 직접 추가도 됩니다.Cursor · Gemini · GitHub Copilot · Hermes · Kimi · Qwen Code 외 25개 이상

에이전트 프로필은 자주 함께 쓰는 설정(프로바이더·모델·생각 깊이·모드)을 「UI 작업」「계획」「검토」처럼 이름 붙여 저장해 두고 한 번에 고르는 기능입니다. 언제 쓸지 메모를 달아 두면 다른 에이전트가 일을 나눠 줄 때 그 메모를 보고 프로필을 고릅니다.

자세히: 3장 에이전트 고르기

5. 기본 흐름 — 여러 일을 동시에 맡기고, 확인하고, 고른다

  1. 시작 — New workspace에서 프로젝트를 고르고 Isolation을 New worktree로, 출발점을 origin/main(서버에 있는 원본 줄기)으로 둡니다. 에이전트와 모델을 고르고 할 일을 보냅니다. 같은 방법으로 두 번째 워크스페이스를 만들면 두 에이전트가 동시에 일합니다.
  2. 검토 — 워크스페이스를 고르고 Changes에서 diff를, Files에서 파일을 봅니다. 다른 의견이 필요하면 같은 워크스페이스에서 New agent로 “파일은 고치지 말고 검토만” 시킵니다.
  3. 실행 · 시험 — New terminal에서 테스트나 개발 서버(만드는 중인 웹 앱을 내 컴퓨터에서 미리 띄워 보는 프로그램)를 돌리고, 웹 앱이면 New browser로 직접 눌러 봅니다. 워크트리는 파일만 따로일 뿐 포트(프로그램마다 따로 쓰는 통신 창구 번호)는 컴퓨터 하나를 함께 쓰므로, 동시에 띄우는 개발 서버는 포트를 다르게 줍니다.
  4. 고르기 — 서로 다른 일이면 브랜치마다 검토해 합치고, 같은 일을 두 방식으로 시켰다면 하나를 고릅니다. 다 쓴 워크스페이스는 보관합니다.

자세히: 2장 · 6장 브라우저 · 따라 하기: 활용편 실습 2, 실습 3

6. 스스로 굴러가게 — 오케스트레이션 · 예약 · 하트비트

기능무엇인가켜는 법 · 만드는 법
오케스트레이션에이전트가 다른 에이전트를 띄워 조사·구현·검토를 나눠 맡기고 결과를 모읍니다. 다른 프로바이더·모델·워크트리·컴퓨터로도 나눌 수 있습니다.Settings → your host → Agents에서 Enable Paseo tools를 켭니다(기본 꺼짐). 그 뒤 새 에이전트에게 “Paseo로 두 번째 에이전트를 띄워 이 브랜치를 검토시켜 줘”처럼 부탁합니다. 일꾼은 입력창 근처 Subagents track에 나타납니다. 셸을 쓸 수 있는 에이전트는 paseo run 같은 CLI로도 됩니다.
예약 (schedule)정한 시간마다 새 에이전트를 시작해 같은 부탁을 실행합니다. 매일 아침 이슈 정리, 보고서, 정리 작업에.앱의 Schedules 화면이 기본. Enable Paseo tools를 켠 뒤 채팅에서 “평일 9시마다 새 이슈를 분류해 요약해 줘”라고 부탁하거나 paseo schedule create.
하트비트 (heartbeat)이미 있는 같은 에이전트를 주기적으로 다시 깨워 상황을 다시 보고 하던 일을 이어 가게 합니다. 오래 걸리는 정리 작업을 끝까지 이어 가기에.Enable Paseo tools를 켠 뒤 채팅에서 “20분마다 스스로 깨어나 이어서 해 줘”처럼 부탁합니다.
헷갈리기 쉬운 것

예약과 하트비트는 시간에 맞춰 움직입니다. 댓글·멘션 같은 바깥 사건으로 에이전트를 시작하는 것은 Hub입니다(8번).

자세히: 4장 오케스트레이션 · 5장 예약과 하트비트

7. 어디서나 연결 — 세 가지 길

길누가 쓰나요점
Paseo 릴레이휴대폰으로 가장 쉽게별도의 망 설정 없이 됩니다. 처음엔 꺼져 있고, Settings → your host → Pair a device → Enable relay 뒤 QR 코드를 폰으로 찍습니다(CLI는 paseo daemon pair). 오가는 내용은 종단간 암호화(양 끝만 풀 수 있게 잠금)되어 릴레이 서버는 읽을 수 없습니다. QR 코드와 짝짓기 링크는 비밀번호처럼 다룹니다.
SSH데스크톱 앱 · CLI에서 다른 컴퓨터의 데몬으로SSH(다른 컴퓨터에 암호화된 통로로 접속하는 표준 방법)로 이미 켜져 있는 데몬에 붙습니다(SSH가 데몬을 설치하거나 켜 주지는 않습니다). Settings → Add host → Remote SSH 또는 paseo --host ssh://user@host ls -a.
Tailscale휴대폰에서 직접 연결Tailscale(내 기기끼리만 통하는 사설망을 만들어 주는 서비스)로 데몬 컴퓨터와 폰을 같은 망에 넣고, 설정 파일의 daemon.listen을 그 주소로 바꾼 뒤 폰에서 Direct connection으로 연결합니다.

8. 더 넓히기 — Hub · 플러그인 · SDK

Hub

데몬들 위에 얹는 층입니다. GitHub·Slack·Discord에서 일이 생기면 에이전트를 시작하고, 트리거(무슨 일이 생기면 시작할지 정한 규칙)를 저장소에 두고 CLI로 배포하며, 무엇이 들어와 무엇이 실행됐는지 기록을 팀이 함께 봅니다. Hub 없이도 Paseo는 그대로 씁니다. → 9장

플러그인

데몬 하나에 설치하는 TypeScript 프로젝트입니다. 화면·사이드바 항목·워크스페이스 패널·명령·프로바이더 등을 더합니다. 게시된 플러그인은 paseo plugin add owner/slug로 설치합니다. → 10장

TypeScript SDK

@getpaseo/client — 내 프로그램에서 데몬을 부려, 프로바이더와 모델을 고르고 에이전트에게 프롬프트와 폴더를 주고 답을 기다립니다. → 10장

9. 자주 쓰는 명령

명령하는 일
paseo데몬을 켜고, 릴레이를 켤지 묻습니다(화면 없는 컴퓨터에서 시작할 때)
paseo run "fix the tests"에이전트를 시작합니다
paseo ls돌고 있는 에이전트 목록 (-a를 붙이면 보관·배경 에이전트까지)
paseo attach <id>에이전트 출력을 실시간으로 봅니다
paseo send <id> "…"추가 지시를 보냅니다
paseo logs <id>에이전트가 한 일의 기록을 봅니다
paseo stop <id>에이전트를 멈춥니다
paseo usage계정 사용 한도와 잔액을 봅니다
paseo daemon status · restart데몬 상태를 보고, 다시 시작합니다
paseo reload설정 파일을 바꾼 뒤 다시 읽게 합니다(재시작이 필요한 항목은 알려 줍니다)

설정과 상태는 ~/.paseo(환경 변수 PASEO_HOME으로 바꿀 수 있음) 아래에 있고, 설정 파일은 ~/.paseo/config.json입니다.

한 줄씩 다시
  • Paseo는 내가 설치한 에이전트들을 내 컴퓨터의 데몬이 돌리고, 여러 앱으로 들여다보는 개발 환경입니다.
  • 단위는 프로젝트 › 워크스페이스 › 세션, 동시에 여러 일을 할 때는 New worktree로 폴더를 나눕니다.
  • 흐름은 시작 → 검토 → 실행·시험 → 고르기입니다.
  • 시간에 맞춘 자동 실행은 예약(새 에이전트)과 하트비트(같은 에이전트), 바깥 사건으로 시작은 Hub입니다.
  • 휴대폰은 릴레이로 짝짓는 것이 가장 쉽습니다.
