git — 파일의 변경을 기록하고,
add → commit → push로 공유하는 도구

git은 버전 관리 시스템(파일이 바뀌는 과정을 시간 순서로 기록해 두었다가 원하는 버전을 다시 불러오는 시스템)입니다. 이 한 장은 git의 핵심 개념과 꼭 필요한 명령 네 개(status · add · commit · push)만 다룹니다.

1. 버전 관리란

파일 하나 또는 여러 개가 시간에 따라 어떻게 바뀌었는지 기록해 두고, 나중에 특정 버전을 다시 불러오는 시스템입니다. 코드뿐 아니라 컴퓨터의 거의 모든 파일에 쓸 수 있습니다. 파일이나 프로젝트 전체를 예전 상태로 되돌리고, 시간에 따른 변경을 비교하고, 누가 언제 무엇을 바꿨는지 볼 수 있습니다.

2. git은 "각자 전부 가지고 있는" 방식

분산형

git 같은 분산 버전 관리 시스템에서는 각자 최신 파일만 받는 것이 아니라 저장소 전체를 이력까지 통째로 복사합니다. 서버가 망가져도 누군가의 복사본으로 되살릴 수 있습니다.

거의 모든 일이 내 컴퓨터에서

git의 대부분 작업은 내 컴퓨터의 파일만으로 됩니다. 보통 네트워크의 다른 컴퓨터 정보가 필요 없습니다.

변경 목록이 아니라 스냅숏

커밋할 때마다 그 순간 모든 파일의 모습을 사진처럼 저장합니다. 바뀌지 않은 파일은 다시 저장하지 않고 이전에 저장한 같은 파일을 가리키기만 합니다.

3. 세 가지 상태와 세 장소 — git에서 가장 중요한 것

파일은 수정됨(modified) · 스테이징됨(staged) · 커밋됨(committed) 세 상태 중 하나에 있습니다. 각 상태는 git 프로젝트의 세 장소와 짝을 이룹니다.

4. 꼭 필요한 명령 네 개 — status → add → commit → push

명령하는 일기억할 점
git status파일들이 지금 어느 상태인지 보여 줍니다"Changes to be committed"는 스테이징됨, "Changes not staged for commit"은 수정했지만 아직 add하지 않음, "Untracked files"는 git이 아직 모르는 새 파일입니다
git add <파일>새 파일을 추적하기 시작하고, 바뀐 내용을 스테이징합니다"이 파일을 프로젝트에 추가"보다 "이 내용을 정확히 다음 커밋에 넣는다"로 생각하면 쉽습니다
git commit -m "메시지"스테이징 영역의 내용을 스냅숏으로 저장합니다-m 없이 실행하면 메시지를 쓰는 편집기가 열립니다. 메시지를 비워 두면 커밋이 취소됩니다
git push <원격> <브랜치>내 커밋을 원격 저장소로 올려 공유합니다예: git push origin master — origin은 원격 저장소의 이름, master는 브랜치(작업 줄기)의 이름입니다. 복제(clone)(원격 저장소를 통째로 내 컴퓨터에 복사)할 때 보통 이 이름들이 자동으로 정해집니다
add하지 않은 변경은 커밋에 들어가지 않습니다

파일을 고친 뒤 git add를 하지 않았다면, 그 변경은 커밋되지 않고 내 컴퓨터에 "수정됨" 상태로 남습니다. 커밋 전에 git status로 확인하는 습관이 안전합니다.

5. 원격 저장소와 push

원격 저장소는 인터넷이나 네트워크 어딘가에 있는 내 프로젝트의 사본입니다. 여러 개를 둘 수 있고, 각각 읽기만 가능하거나 읽고 쓸 수 있습니다. 함께 작업하려면 원격 저장소를 다룰 줄 알아야 합니다.
